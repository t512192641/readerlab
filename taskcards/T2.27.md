- 总控只直接管理一个新的 `gpt-5.6-terra / medium` 生产小组长。

- 总控和小组长不得创作、摘要、重排或改写 P1 候选、lesson 或产品审阅正文。

## P1

Expert 只读取冻结的 `locked/chapter-scope.xhtml`。它可以沉默；若有值得继续投入的发现，每个候选必须包含：

- 唯一 ID `C-01` 起；
- 中文标题；
- 从本章逐字复制、足以判断关系的原文摘录；
- 想完整讲授的一堂课及核心判断；
- 该课离开原文后的独立学习价值；
- 原文在课程中的实质作用；
- 若进入 P2，准备怎样完整展开。

Expert 先写工作区外候选。小组长必须验证 UTF-8、ID 唯一、字段完整、原文摘录逐字存在于冻结 scope、没有其他 run 内容后，才排他 promotion 为 `raw/p1-candidates.md`。正式文件首次写入后不得修改。

总控复核 bytes、SHA、source excerpt 和 read-set 后，将该单一文件交产品负责人 P1。P1 只判断哪些候选值得同一 Expert 继续展开。总控仅机械写入 `locked/p1-gate.md`，其中只含获选 ID 和 `P1_PASS`；没有获选对象则实验以合法 P1 停止。

## P2

同一 Expert 只能读取：

- `locked/chapter-scope.xhtml`
- `raw/p1-candidates.md`
- `locked/p1-gate.md`

每个获选候选分别在工作区外形成完整 lesson。lesson 必须保留候选核心判断，包含相关原文摘录、完整知识结构、原文的实质作用、迁移判断和必要边界；不得读取其他 run、产品理由、Writer、Fidelity、Rater 或历史答案。

小组长逐份验证候选 ID、P1 gate、原文摘录逐字存在、UTF-8 和必需章节后，排他 promotion 为 `final/<candidate-id>-lesson.md`。`acceptance/acceptance-report.md` 只允许以固定标题和这些冻结 lesson 的完整 bytes 顺序拼接，不得摘要、删减或重排；`acceptance/judge-predictions.md` 只写 `NOT_RUN_OUT_OF_SCOPE`。

production 完成后使用现有 `tools/run.py freeze`；acceptance 两文件完成后使用 `tools/run.py freeze --acceptance`。产品负责人只读取 `acceptance/acceptance-report.md` 给出 P2 判词；判词冻结到 `acceptance/product-verdicts.md` 后运行 `tools/run.py check`，然后停止。
