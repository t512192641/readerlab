# T4.2 透镜登记册最小实现

## 1. 任务编号与标题

`T4.2`：透镜登记册最小实现。

## 2. 目标

以版本化记录保存每个透镜的战绩与人工复盘建议。

## 3. 允许读取清单

- `AGENTS.md`
- `PRODUCT-DECISIONS.md`
- `ENGINEERING-LESSONS.md`
- `blueprints/EXECUTION-ROADMAP.md`
- `contracts/GLOSSARY.md`
- `lenses/T1.9-seed-lenses.md`
- `lenses/T2.3-seed-lenses-v2.md`
- `lenses/T4.1-performance-ledger.md`
- `diagnostics/T4.1-freeze-receipt.md`
- `taskcards/T4.2.md`

## 4. 交付文件清单

- 创建 `lenses/registry/index.md`
- 创建且仅创建冻结 `lenses/T4.1-performance-ledger.md` 逐字枚举的 registry 文件；这些路径必须位于唯一根 `lenses/registry/`，receipt 必须绑定同一 ledger SHA-256。

## 5. 硬约束

- 依据 `PRODUCT-DECISIONS.md`“正式透镜的演化”：版本不可原位覆盖，必须保存使用结果、合格／质疑／失败及原因；系统只能提出建议，人工定期复盘决定继续、调整或退役。
- 依据路线图“专家、透镜与持续改进”及 T4.2：不自动覆盖、删除、降级或退役；工程冻结不等于产品事实变化。
- 依据 T0.1 的闭合集例外：ledger 在派发前逐字枚举精确路径，receipt 绑定其 hash；不得用 glob、推断、占位符或额外文件扩张交付范围。
- 创建每个版本记录前，核对 ledger 中该记录的 source lens 相对路径与 SHA-256 和实际文件一致；不一致即 blocker，仍禁止自动升降或退役。

## 6. 完成判据

机械：index 与 ledger 逐字枚举的每个独立版本文件均有状态头、版本、战绩、建议和保留原因，且没有其他 registry 文件。主控：确认 receipt hash 匹配、没有自动修改透镜等级、版本或产品 owner 文档。
