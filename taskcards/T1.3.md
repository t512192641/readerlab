# T1.3 发现合同

## 1. 任务编号与标题

`T1.3`：发现合同。

## 2. 目标

定义从 B1 发现值得深入的透视需求的最小结构。

## 3. 允许读取清单

- `AGENTS.md`
- `PRODUCT-DECISIONS.md`
- `ENGINEERING-LESSONS.md`
- `blueprints/PIPELINE-MAP.md`
- `blueprints/EXECUTION-ROADMAP.md`
- `contracts/GLOSSARY.md`
- `taskcards/T1.3.md`

## 4. 交付文件清单

- 创建 `contracts/T1.3-discovery.md`

## 5. 硬约束

- 依据 `PRODUCT-DECISIONS.md`“图书线：已确认的产品主线”第 3 项：真实缺口才创建临时专家，受控偶遇允许没有发现，禁止凑数。
- 依据路线图 T1.3：透视需求含位置锚点、为什么值得停下与期望增量类型。

## 6. 完成判据

机械：合同以 `status: draft`、`scope: long-term` 起始，并列出三字段、零发现合法和禁止凑数。主控：确认未把发现模型、阈值或调用合同擅自冻结；M1 前不得自称 frozen。

### M1 主控技术门返工

- `contracts/T1.3-discovery.md`：只补齐每次必须完成一次受控偶遇探索，以及“为什么值得停下”必须承载一个清楚、单一、值得深入的问题。
- `blueprints/EXECUTION-ROADMAP.md`：只同步上述受控偶遇、零发现与单一问题责任。
- 探索后仍允许零发现并禁止凑数；模型、阈值、调用方式、完成证据字段与 schema 不冻结。
