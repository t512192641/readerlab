## 5. 硬约束

- 依据 `PRODUCT-DECISIONS.md`“图书线：已确认的产品主线”第 7 项：冻结后独立验收结合原文、开放金标、正反例和五项标准；产品负责人给最终判词。
- 依据路线图 T3.6：先核验 M2 receipt 记录的 M1 receipt SHA-256 与实际 `contracts/M1-freeze-receipt.md` 一致，再用实际 M1 receipt 核对 T1.8 SHA-256，继而用 M2 receipt 核对 T2.1／baseline SHA-256；最后才读取并使用这些冻结正文。receipt 只核验身份与 hash，不替代正文；先以 final receipt 绑定 T3.1 根 receipt，再冻结 production，继而创建并冻结以稳定 `b2-item-id` 为键且保留 knowledge-card／producer 回链的 judge predictions 与 acceptance report，暂停供主控做 M3；仅 M3 通过后，才以同一键由产品负责人给惊艳／有用／平庸／废弃及死因并写 verdicts；这是 80 分验收点。
- 依据 `ENGINEERING-LESSONS.md` 经验一：报告必须分 execution、semantic、product，任一层不能替代另一层。
- 依据路线图 M2：无 `diagnostics/M2-gate-receipt.md` 不得开始独立验收。
- T1.8、T2.1 与 baseline 任一 SHA-256 或 M1→M2 receipt 链不一致即 blocker。
- 顺序固定为：`runs/T3.1/freeze-receipt.md` → `runs/T3.1/final/freeze-receipt.md` → `runs/T3.1/production-freeze.json` → `judge-predictions.md` 与 `acceptance-report.md` → `runs/T3.1/acceptance/acceptance-freeze.json` → M3 → `product-verdicts.md`。final receipt 必须包含且只包含一个可机械读取的 `t3.1-freeze-receipt-sha256: <64 lowercase hex>` 绑定字段，其值等于根 receipt 的实际 SHA-256；production freeze 与 frozen `check` 都复核该绑定。production 清单只锁 `run.json` 与 `raw`／`locked`／`final`，不把根 receipt 列入 `files`，但 final receipt 自身属于冻结面；acceptance 清单必须绑定 production 清单 SHA-256，并锁定 predictions/report。
- 无 production 清单时 `acceptance/` 不得有文件；acceptance 清单创建前 `product-verdicts.md` 不得存在。acceptance 冻结后只允许晚到的 `product-verdicts.md`，predictions/report 的改动或其他 acceptance 路径的新增均为机械失败。
- 单写者边界：每次 `tools/run.py new`、`freeze`、`check` 执行期间，显式 root、材料路径与 `runs/T3.1/` 只能由当前调用者写入；外部并发写入不在 T0.2 轻骨架保证内，不得据此引入锁、lockfile、状态机、数据库、第四个子命令或受控写命令。

## 6. 完成判据

机械：先确认 `runs/T3.1/freeze-receipt.md`，再创建并核验正确绑定它的 `runs/T3.1/final/freeze-receipt.md`；随后由 `tools/run.py freeze runs/T3.1` 创建 `runs/T3.1/production-freeze.json` 并以 `tools/run.py check runs/T3.1` 通过。之后 judge predictions 与 acceptance report 以 b2-item-id 为键保留回链，再由 `tools/run.py freeze runs/T3.1 --acceptance` 创建并核验 `runs/T3.1/acceptance/acceptance-freeze.json`。M3 检查时两份清单及 predictions/report 存在且 `product-verdicts.md` 不存在；只有 M3 通过后，同键的 product verdicts 才可出现，出现后 `tools/run.py check runs/T3.1` 仍须通过。

主控：确认验收未回写 production 冻结面，两份清单路径和顺序与本卡逐字一致，且 `accepted` 仅来自产品负责人；未通过 M3 时停在 verified/unknown，不生成 verdicts。
