## 5. 硬约束

- 依据路线图“总体架构：轻骨架、合同与执行 Agent”与 T0.2：只做 `new`、`freeze`、`check`，纯标准库、单文件；不得实现状态机、数据库或调度器。
- 依据 `ENGINEERING-LESSONS.md` 经验二：材料身份、目标不存在、目录隔离、preflight／postflight 与冻结必须可确定性检查。
- 依据 `PRODUCT-DECISIONS.md`“材料进入与范围冻结”：来源或范围未确认必须阻塞，不得猜测；生产路径禁读金标与样张。
- `new` 必须把材料保存为显式 root 下的相对路径；`freeze` 与 `check` 都复核该路径的真实 `sha256` 与 `bytes`。不存在时报 `material missing / 材料丢失`，身份不同时报 `material changed / 材料被改`。
- 第一份 production 清单固定为 `<run>/production-freeze.json`，只冻结 `run.json` 与 `raw`／`locked`／`final`；第二份 acceptance 清单固定为 `<run>/acceptance/acceptance-freeze.json`，绑定第一份清单身份并冻结 `judge-predictions.md` 与 `acceptance-report.md`。
- production 冻结前 `acceptance/` 必须为空；production 冻结后才可写 predictions/report；acceptance 冻结前禁止 `product-verdicts.md`，冻结后只放行该 late verdict 路径，其他 acceptance 增删改仍失败。
- run 根只额外放行普通文件 `freeze-receipt.md`，不得是符号链接；它不属于 production 清单的 `files`。若该根 receipt 存在，production freeze 前必须已有 `final/freeze-receipt.md`，并以 `t3.1-freeze-receipt-sha256: <64 lowercase hex>` 精确绑定根 receipt 的实际 SHA-256；production freeze 与 frozen `check` 都必须复核，且 final receipt 自身由 production 清单冻结。
- 无 `production-freeze.json` 时，`check` 必须验证 run metadata、真实材料、production 目录树的普通文件／目录与符号链接边界、空 acceptance、根 receipt 类型与可选状态头，退出 0 并明确报告 `production=open`；存在 production 清单后继续执行 frozen 校验。
- `materials/.gitignore` 默认忽略 EPUB、PDF 与任意源材料，只放行根级 `.gitignore`、任意层级既有 `.gitkeep` 和任意层级精确命名的 `authorization.md` 元数据；验证器必须拒绝嵌套 `.gitignore` 和 Git index 中的其他材料。
- 在每次 `new`、`freeze`、`check` 调用期间，显式 root、材料路径与 run 目录只能由当前调用者单写；外部并发写入不属于本轻骨架保证。不得为此加入锁、lockfile、状态机、数据库、第四个子命令或受控写命令。

## 6. 完成判据

机械：`python3 validate.py`、`python3 -c "import ast, pathlib; ast.parse(pathlib.Path('tools/run.py').read_text(encoding='utf-8'))"` 和任务内的临时目录 smoke check 均退出 0，且仓库内无 `__pycache__` 或 `.pyc`。

临时目录 smoke 必须逐项证明：直接执行 `tools/run.py --help/new/freeze/check`；`new` 成功且重复 `new` 不覆盖；pre-production `check` 对 T3.1 根 receipt 与 T3.2 raw/postflight 路径报告 `production=open`；production freeze 与 `check` 成功；production 增删改可发现；有效状态头通过；材料删除与材料修改分别失败且错误类型不同；production freeze 前 acceptance 文件被拒；production freeze 后 predictions/report 可写；acceptance freeze 成功且绑定 production；acceptance freeze 前 verdict 被拒、冻结后 verdict 可出现且 `check` 通过；其他 acceptance 新增或修改被拒；根 receipt 为符号链接时失败；final receipt 缺失、错误 hash 时失败，正确绑定时通过；完整 T3.6 顺序无死路。

临时 Git 仓库 smoke 必须证明：`git check-ignore --no-index` 对 `materials/T3.1/source.epub` 退出 0、对 `materials/T3.1/authorization.md` 退出 1；嵌套 `.gitignore` 企图放行源材料时验证器失败；强制暂存 `source.epub` 后验证器失败。

主控：确认两份冻结清单与 T3.6 路径完全一致、顺序无死路、run 路径不可覆盖、检查不替代语义或产品验收。
