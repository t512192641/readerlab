## 5. 硬约束

### 历史 v1（已结束，不是当前 gate）

v1 使用 3 个正例、8 个反例和 3 个 book reference，共 14 个固定对象。该次执行已经完成，考试结果为失败；其盲包、计分与产物只保留历史证据身份，不再构成当前 active gate。

### 当前 v3 校准（唯一 active gate）

当前对象是 v2 已冻结的 12 项 source 与 candidate。v3 必须逐字复用 v2 的 `packet.md`，保持题目、顺序、ID、source 与 candidate 不变；只把 `PRODUCT-DECISIONS.md` 中已经落库的通用 B2 产品门槛加入 fresh judge 的裁判标准。

当前唯一计分 gate：

- `CASE-K7M2Q`、`CASE-V8H3L` 两个 positive 必须判 `放行`；
- `CASE-C2F6P`、`CASE-J9W4D`、`CASE-Q3L7X`、`CASE-H6N2B`、`CASE-T8C5R` 五个 hard negative 必须判 `拦截`；
- `CASE-M5A8S`、`CASE-D4V9K`、`CASE-P7G3M` 三个 non-pass borderline 只能判 `边缘` 或 `拦截`，不得判 `放行`；
- `CASE-B9Q5J`、`CASE-L3E7W` 两个 reference 只记录，不进入硬门。

v3 仍须在冻结输入后由 fresh judge 一次处理全部 12 项，并保持生产答案、金标、逐题判词、计分键与 judge 隔离。只有上述三类硬门全部满足，校准结果才为 `PASS`。

同题 v3 `PASS` 只表示裁判能够用新标准解释产品负责人已经给过答案的固定对象，不表示已经取得未知材料上的泛化资格。无论校准为 `PASS` 或 `FAIL`，都不得据此进入 M2、T3 或真实图书生产。

## 6. 完成判据

### 可机械检查

- v3 packet 与 v2 packet 字节相同且 SHA-256 不变。
- fresh judge 只按冻结输入闭集运行一次，答案先于计分键冻结。
- v2 verifier、v3 verifier 与根验证器全部通过。
- 两个本地 commit 的路径范围分别符合产品标准增量与 run 增量。

### 主控核验

- 产品事实只进入 `PRODUCT-DECISIONS.md`，固定对象判词只进入 `GOLD-STANDARDS.md`。
- T1.8、example 正文、v2 run 与历史 diagnostics 均未修改。
- 如实记录校准 `PASS` 或 `FAIL`，不按成绩修改冻结输入、答案或补跑。
- 未创建 M2 receipt，未进入 T3，未 push。

### 验收层级

- `implemented`：owner、当前 gate 与完整 v3 run 文件存在。
- `integrated`：摘录、brief、packet、answers、后置 key、receipt、report 与 verifier 形成一条真实 run 证据链。
- `verified`：三个验证器与 Git 范围检查通过。
- `accepted`：产品负责人的既有标准与逐题判词已经落库；本次 judge 校准结果不是新的产品判词。
