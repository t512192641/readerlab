## 3. 可执行硬门

唯一控制入口为 `scripts/t226_p2_recovery.py`。它必须在任何正式写入前：

1. 将 run 现存路径与本卡允许集合逐项比较，拒绝未知路径和任何 P2 后续产物；
2. 逐文件核对本节冻结的路径、bytes、SHA、P1 gate 中性结构及旧 registry；
3. 在工作区外生成候选 P2 v02、三份分轴验证结果、candidate manifest
   和 P2 v02 registry；
4. 证明候选包等于固定 wrapper 与两份 lesson 原始 bytes 的确定性拼接，
   且每份 lesson 原始 bytes 各完整出现一次；
5. 拒绝摘要、删减、改写、重新排序、额外语义解释或模型撰写的
   “机械装配”；任何不能由固定模板和冻结 bytes 唯一重建的包均失败；
6. 先让候选控制代码、测试与本卡通过测试和 Standards／Spec 双轴审查；
7. 只在双轴均为 `PASS`、候选完整复验通过且正式目标仍不存在时，
   将完全相同 bytes 以 `O_EXCL` 排他首次写入，再二进制回读；
8. 先晋升 P2 v02，再晋升三份分轴结果，最后晋升 versioned registry；
   不创建最终 root registry。

正式 artifact 不得先写入后测试。候选验证、双轴审查、正式晋升和正式回读
必须是四个可区分事件。晋升中断时保留首次事实并停止，不覆盖、不截断、

## 5. 三条独立验证轴

- **provenance**：证明 lesson 路径、bytes、SHA、顺序、完整出现次数，
  以及 P1 gate 的中性身份；不评价内容。
- **contract**：证明允许路径、阶段状态、候选在工作区外、确定性拼接、
  候选先验验证、排他晋升、旧 bytes 保留、无后续产物和零语义调用；
  不评价内容。
- **product-ready**：只证明 v02 达到“可交产品负责人审阅”的技术状态，
  必须写明 `product_verdict: NOT_MADE`、`p2_gates: NOT_CREATED`、
  `downstream: BLOCKED_PENDING_PRODUCT_REVIEW`；不得给产品建议或判词。

registry 只证明登记路径当前 bytes 的 integrity。它不得把 integrity、
provenance、contract 或 product-ready 合并成一个“通过”，也不得充当
产品接受、P2 gate 或后续生产许可。
