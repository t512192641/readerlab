## 7. Closeout gate

任务结束前逐项核对：

1. 若本任务生成受候选／promotion／freeze 规则约束的正式 artifact，它已按规定顺序取得
   稳定身份；应生成但未形成时明确 `unknown` 或 `BLOCKED`。本任务不生成该类 artifact 时

2. 若出现产品判词，任务卡或获批 run 文件必须有且只有一个“产品判词”二级标题；
   `docs/current-task.md` 的 `product-verdict-source` 必须指向该文件，并与同一任务、对象和终局
   同步。若本卡未预先授权该 owner，则不得宣称 closeout 完成。
3. 当前停止点、允许动作、禁止动作及下一生产动作的授权状态已经明确；产品接受不自动授权
   Writer、新 run 或下一阶段。
4. 完成报告先列出本轮创建或修改过的全部 run 和文件，再分别报告
   `implemented`、`integrated`、`verified` 与 `accepted`。
5. 运行本卡列出的确定性检查，并由主控复核真实入口、Git diff、未跟踪文件和冻结身份。

任务卡顶部的 `closeout-result` 是唯一机器可检索终局 owner。收尾时必须把它从
`IN_PROGRESS` 更新为：

- `closeout-result: PASS|BLOCKED`

会话完成报告只引用本卡的当前终局，不拥有第二份机器字段；该回显一致性由主控核对，active
tests 只自动检查仓库任务卡。任一必需项缺失时使用 `BLOCKED`，保持当前生产停止点，不得以
“任务主体已经完成”绕过收尾。
