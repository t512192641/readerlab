# ReaderLab 流水线开发蓝图

> 这是从 `PRODUCT-DECISIONS.md` 派生的长期架构地图，不新增产品决议，也不假装具体合同或 Skill 拆分已经确定。产品决议改变时先改 owner，再同步本图；一次性任务卡不得改写本图。

## 图书线

```text
材料进入
  ↓ 冻结本次阅读范围
B1 作者原文
  ↓ 专家阅读、自由发现与完整认知
专家认知初稿／可读 Demo
  ↓ 内容价值与事实审核
通过内容判断的认知资产
  ↓ Writer 编辑、忠实性复核与装配
B2 原文附近的高手讲解
  ↓ 声明范围确实读完
B3 读薄
  ↓ 产物冻结
独立产品验收
```

Expert、Judge、Writer、核验和装配描述的是功能责任，不预先决定它们是否成为独立 Skill、同一 Skill 内的隔离调用或其他实现。长期硬边界是各阶段只取得完成自身责任所需的信息，并通过冻结产物交接；具体技术拆分留给后续选型。

### 正式透镜的治理支线

正式透镜不是一次生成后永久不变的名单。每个版本要保存使用结果，以及“合格、被质疑、失败和原因”；系统可以汇总数据并提出升降、调整或退役建议，但不能静默覆盖或删除。人工定期复盘后才改变状态。阈值、周期、执行者和界面尚未冻结。

### 当前日常生产路线假设

下面只是为目标档模型降低单步认知负担、提高可诊断性而提出的当前实现假设，不是产品目标或已冻结合同：

```text
完整章节
  ├─ 控制层只重建章节论证地图，不生成知识或给专家派题
  └─ 自动生成主线相关与开放跨领域两类稳定认知背景
        ↓ 多个专家各自完整、自由阅读；可以沉默
自然发现“可以借这段原文讲一堂什么课”
  ↓ 控制层按知识问题与谱系聚类，检查重复、偏科与新课程家族
课程入口版图
  ↓ 新波次不再产生有价值的新家族时停止发现；不以固定专家数或课程数停止
  ↓ 控制层判断真实触发、案例必要性、独立价值、主干性、生长性与认知成本
成立的课堂入口
  ↓ 交回同一专家，按知识自身结构完整授课
专家课初稿
  ↓ 课后显化成熟知识、专家综合与原文应用的来路
  ↓ 来源与事实核验，只纠错和标注，不替专家重定课程
  ↓ 锁定承重语义后减少支线、重复和同时教学的知识数量
高密度课堂讲义
  ↓ 忠实性、独立价值、迁移能力、阅读成本与边界审核
候选读者文本
  ↓ 忠实性复核与完整章节阅读验收
完整章节内保留不同专家声音的评论
```

当前假设把专家当作会把原文带进自己课堂的真实读者，而不是接受中央约稿的问题回答者、短评生产器或展示指定领域知识的角色。控制层先从完整章节重建作者的承重命题、重要分支、例证与开放问题，这张地图只用于后置选择和组织，不进入专家 Prompt。自动选角同时覆盖能够深化本章主要问题的认知背景和不受主题封闭的跨领域背景；所有专家仍完整自由阅读，不预分配问题、结论、知识类型或锚点。

生产、内容判断、编辑和验收必须使用彼此隔离的读取闭集；当前已经测通的手工方式是新上下文、逐项输入白名单与冻结文件交接。该隔离责任不要求提前决定最终 Skill 拆分。

本路线假设的历史依据只由 `ENGINEERING-LESSONS.md` 的相关经验和 `taskcards/T2.2.md` 的运行记录拥有；本图不复制评分、候选数量、成本或失败归因。由这些 owner 派生到当前路线的唯一结论是：真实关联与独立学习价值必须同时成立，完整专家认知与最终读者组织必须分层，来源核验不能替代选题价值，技术完成不能自动晋级。

具体实验的晋级和停止顺序只由当前任务卡拥有。本图只保留长期架构和可替换实现假设；旧样段、知识卡 gate 或完整 B1 Writer 输入均不得从历史段落恢复为现行合同。

“读厚再读薄”在组织层体现为先让读者接上领域主干，再决定是否打开精确支线。领域主干不是“最有名的人”，而是能组织该领域大问题、核心机制和可复用判断的知识结构；冷僻理论只在不可替代地提高解释力或与原文特别吻合时承担正文篇幅。高密度讲义按“问题与框架在前、人物与来源按需出现”组织，不能再次压成来源逐项陈列的文献综述。

新方案执行前由控制层做能力保留审查：是否重新引入固定课程数、来源数、概念数或字数；是否替专家命题；是否把连贯课程误成一个局部观点；是否为核验排除实践、历史、书籍框架或跨领域综合；是否为压缩删掉承重推理。该清单只约束流程设计，不进入专家 Prompt。

知识卡、来源表和章节地图仍只是内部审计材料。Writer 的稳定编辑边界由 `PRODUCT-DECISIONS.md` 拥有；历史路线中的单卡、固定焦点或完整 B1 输入不构成现行权限。

## Skills 线

```text
材料进入
  ↓
如果是大型 Skill 包：先给导航与聚类
  ↓ 但仍须逐个读取适用 Skill
E1 完整中文净化正文（必交）
  ├─ E2 给产品负责人的非技术陪读
  ├─ E3 给产品负责人的技术讲解
  └─ E4 给 Agent 的独立资产卡
        ↓
四个产物分别验收；E2/E3/E4 可分别为零
        ↓
三者全零时至少复核一次
```

| 环节 | 必须做到 | 不能混淆 |
|---|---|---|
| 包级导航 | 告诉用户有什么、何时读哪个 Skill | 导航不能代替逐 Skill 阅读 |
| E1 | 忠实、完整、可回溯的中文主体 | 摘要不能冒充正文 |
| E2 | 给不懂技术的产品负责人讲明白 | 可以为解释而整理改写；不套用图书 B2 的跨行业增量门槛 |
| E3 | 讲清机制、取舍、失败边界，使技术认识可复用 | 不是工程师复盘；不套用图书五项标准 |
| E4 | 让无背景 Agent 能正确判断、行动和复用 | 与 E1—E3 分开交付；Agent 不是第二个人类用户 |
| 分别验收 | 每个适用产物独立到达合法终局 | 一个产物不能替另一个抵消失败 |
