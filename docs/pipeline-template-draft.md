# Readerlab 三层流程模板草稿

本文档是三层架构的固化模板。标注了哪些是硬编码（HARD）、哪些是可选（SOFT）。
产品负责人需审阅所有 HARD 项。

## 版本

- v1.1 — 基于 T2.15–T2.24 实验结果及最终决议修订
- 适用：图书章节的框架化陪读生成

---

## 一、角色-会话映射

| 角色 | 会话要求 | 理由 | 类型 |
|---|---|---|---|
| Expert（发现 + 展开） | 两个同源分支，互不读取 | 同源隔离防止交叉污染（T2.20 已验证） | HARD |
| 比较者 | 独立会话 | 解决承诺偏差（T2.18 已证明） | HARD |
| Writer ×N | 独立会话 | 只读冻结专家课 + 交接包，不读原文全文 | HARD |
| 忠实性检查 ×N | 独立会话 | 不读 Writer 指令，只读专家课 + Reader | HARD |
| 控制层机械扫描 | 不调用模型 | 扫描 Expert 台账，识别跨学科概念拼接 | HARD |
| 装配 | 不调用模型 | 确定性操作，SHA-256 校验 | HARD |

各步骤中的 `N` 表示该步骤实际处理的对象数，不是固定上限；进入 Expert 展开、进入 Writer 和最终装配的对象数可以不同。模型会话实例数随实际对象数变化；机械扫描和装配不调用模型。

**来源审核**：不再独立环节，合并进 Expert 展开的台账标注。
**旁路诊断**：砍掉。
**P1**：开发期和生产期都由确定性规则自动处理；开发期保留输出供回看。

---

## 二、总体流程

```
发现 → 比较 → P1 自动门 → Expert 展开 → 机械拼接扫描 → Writer 编辑 → 忠实性检查 → 装配
```

第三章压力测试阶段在 Expert 展开后保留 P2 人工门、在忠实性检查后保留 P3 人工门。第三章通过后，正式 Skill 撤掉全部人工门：用户输入 EPUB + 章节号，自动输出带 0-N 个陪读的完整章节 Markdown。

| 步骤 | 模型调用 | 可并行 | 人工门 |
|---|---|---|---|
| 1. Expert 自主发现 | 1 | 否 | 否 |
| 2. 独立比较者筛选与比较 | 1 | 否 | 否（P1 自动处理） |
| 3. Expert 展开（通过阈值的全部候选） | N | 是 | 否 |
| 4. 控制层机械拼接扫描 | 0；触发时 +1 次轻量检查 | 否 | 否 |
| 5. P2 产品判词 | 0 | 否 | 仅第三章压力测试阶段 |
| 6. Writer 编辑 | N | 是 | 否 |
| 7. 忠实性检查 | N | 是 | 否 |
| 8. P3 产品判词 | 0 | 否 | 仅第三章压力测试阶段 |
| 9. 装配 | 0 | 否 | 否 |

模型调用不再固定为 8 次：按各步骤实际对象数和是否触发拼接轻量检查计算。第三章压力测试保留 2 次人工门；正式 Skill 为 0 次人工门。

## 三、Step 1：Expert 自主发现

### 输入

- 完整章节的冻结文本
- 上一章的已选框架列表（避免同一本书内重复，可选）

### 输出

1. 章节结构动作（3-5 个，不是逐段摘要）
2. 候选框架列表（数量由发现质量决定，不作为后续展开配额）
3. 每个候选：名字、学术来源、一句话身份、回应哪个结构动作、可能改变什么

### 硬约束（HARD）

1. 候选必须有学术来源，不能是本节 AI 现场编造的概念
2. 候选不能只是对原文某观点的"正反辩"或"新视角"，必须是可迁移的认知装置
3. 候选池输出时不展开，只给名字、来源、一句话理由
4. 不预设候选数量，不限制学科来源

### 质量检查（SOFT）

- 候选是否覆盖本章不同结构面？
- 候选是否全部停留在同一分析层级？（如果是，记录为观察但不阻塞）

---

## 四、Step 2：独立比较者筛选与比较

### 输入

- 完整章节冻结文本
- Step 1 产生的候选池

### 输出

- 对每个候选的独立展开判断：`WORTH_EXPANDING`、`MARGINAL` 或 `NOT_WORTH`
- 每个候选的判断理由，逐条回答五项可迁移性检查
- 支配/互补关系说明
- `unknown` 标注

不预设展开数量。通过质量阈值的候选全部进入 Expert 展开；一章可以产出 0、1、3 或 5 个陪读。软上限为 3-4 个，超过 4 个时提醒阅读负担过重，但不阻断流程。

### 五项可迁移性检查（全部 HARD，不可跳过）

| 编号 | 检查项 | 必须回答的问题 |
|---|---|---|
| C1 | 独立知识 | 拿掉原文后，还剩下什么稳定知识？ |
| C2 | 内部组织 | 它内部靠什么区分、关系、过程或判断方式成立？ |
| C3 | 跨场景迁移 | 换一个不同场景，读者具体怎样使用？ |
| C4 | 既存与补造 | 哪些结构已存在于候选描述，哪些需要专家临时补造？ |
| C5 | 合理阅读成本 | 能否在合理阅读成本内保留承重结构？ |

每项检查都必须标注 `PASS`、`INSUFFICIENT` 或 `unknown`，并附一句理由。

### HARD 约束

1. **C1-C5 必须全部显式回答**，不能选择性跳过。如果某项无法回答，标 `unknown` 并说明原因。
2. **判定理由必须锚定在"这段原文的认知增量"上**，不是框架的抽象强弱。
3. **发现型候选必须被识别**：如果一个候选主要是"你以为 X，其实不是 X"的一句话反转，且没有独立变量体系，优先判为 `NOT_WORTH`，并在理由中说明。允许例外：如果这个翻转具有跨场景的持续诊断力（如休谟的事实-价值区分），可以保留为高质量候选，并说明其诊断力来自哪里。
4. **unknown 诚实标注**：比较者不知道的必须说不知道，不能为了判定完整性而编造判断。
5. **第四条检查中，如果所有候选都标"结构自足"**，视为强警报，标记 `NEEDS_REVIEW`。
6. **判定不能只看"认知增量"**，必须同时检查"可迁移性"和"需要补造的量"。

### 候选判定阈值（HARD）

对每个候选独立判定：

- `WORTH_EXPANDING`：五项检查中没有 `INSUFFICIENT`，且至少三项为 `PASS`
- `MARGINAL`：有认知增量，但被更强候选支配，或内部结构偏薄
- `NOT_WORTH`：发现型、一句话反转、或与原文重叠过大，且不满足上面的例外

`MARGINAL` 和 `NOT_WORTH` 不进入本轮 Expert 展开，但保留在候选池记录中。若没有任何 `WORTH_EXPANDING`，标记“本章无合适框架”，不硬塞陪读。

### SOFT 建议

1. 支配关系可以用"A 的覆盖范围包含 B"或"A 提供的机制比 B 更底层"表述
2. 互补关系可以用"A 和 B 覆盖原文不同结构面"表述
3. 如果两个候选无法分出高下，平局是可以接受的

### P1 自动门规则

| 条件 | 处理 |
|---|---|
| 所有候选的 C1-C5 均显式回答，且各候选已按阈值完成独立判定 | **自动放行** |
| 至少 3 项回答为 `unknown` | 标记 `NEEDS_REVIEW`，人工介入 |
| 无任何 `WORTH_EXPANDING` | 标记 `NO_FRAMEWORK`，继续输出 0 个陪读 |
| 无法完成候选判定或比较信息相互矛盾 | 标记 `FAILED`，开发期人工介入 |

`NEEDS_REVIEW` 和 `FAILED` 的情况保留人工 override 权。
P1 自动放行不意味着跳过——比较者输出和候选判定保留在审阅稿中，产品负责人可事后回看。正式 Skill 中不阻塞生产；开发期仍可人工介入 `NEEDS_REVIEW` 和 `FAILED`。

## 五、Step 3：Expert 展开

### 输入

- 完整章节冻结文本
- 比较者对全部候选的独立判定
- 所有 `WORTH_EXPANDING` 候选的冻结描述和判断理由

### 输出

- 每候选一份完整专家课（不设固定篇幅，由知识复杂度决定）
- 新增台账：标注每项内容的来源性质
- 来源归属表
- 锚点选择（Expert 自主选择，不接收外部指定）

### 五条验收标准（全部 HARD）

| 编号 | 验收项 | 标准 |
|---|---|---|
| E1 | 独立学习价值 | 拿掉原文后，知识对象仍有独立学习价值 |
| E2 | 内部可跟随 | 读者能跟随它内部的关系、过程、区分或操作 |
| E3 | 跨场景迁移 | 至少一个非本章场景的迁移示例，具体、有诊断力 |
| E4 | 原文案例作用 | 原文在课程中承担真实案例作用，不是被贴标签 |
| E5 | 无隐藏补造 | 没有靠临时补造结构通过 |

### 新增台账（HARD）

专家课末尾必须有新增台账，逐项列出：

| 新增内容 | 来源性质标注（必选其一） |
|---|---|
| 核心概念 | `CLAIMED_EXISTING`（声称来自既有学术传统，附人名/著作）/ `EXPERT_SYNTHESIS`（专家综合）/ `TEACHING_TERM`（教学性工作术语）/ `SCENARIO`（说明性案例）/ `UNKNOWN`（待核验） |
| 变量或机制 | 同上 |
| 边界 | 同上 |
| 迁移场景 | 同上 |

### 来源归属标注（HARD，替代独立来源审核）

在专家课中，对每个框架的核心概念，必须标注：

1. **这个概念来自谁/哪个传统**（具体到人名和著作）
2. **哪些是既有理论的原始内容**
3. **哪些是你在展开时的综合或教学性改写**
4. **如果不确定来源，或两个概念来自不同学术传统，标为 `UNKNOWN`**

### Expert 完成后的机械拼接扫描（HARD）

这是控制层的确定性扫描，不调用模型。Expert 展开完成并提交核心概念台账后，扫描器执行一次正则匹配：

- 同一堂课的核心概念台账中出现至少 2 个不同学者名字；且
- 这些学者通过维护的学科关键词表被识别为不同学科（例如心理学/认知科学、政治学/人类学、哲学、经济学）。

满足两项即自动标记 `CONCEPT_STITCH`，不依赖 Expert 是否自行意识到拼接。学者归属无法从关键词表确定时，标记 `UNKNOWN`，不把未知当作同一传统。

### `CONCEPT_STITCH` 轻量检查（仅在扫描触发时）

1. 触发一次模型检查，只审这一项拼接的合法性，不全文审查
2. 判断两个概念能否合法并置，还是必须拆成两个独立框架
3. 如果必须拆开，Expert 重写该部分
4. 未触发时不追加轻量拼接检查；来源归属仍按 Expert 台账要求保留

Expert 可以主动标注疑似拼接，但主动标注不能替代机械扫描。

### SOFT 建议

1. 各份专家课独立冻结，不预先合并
2. 多个候选不要合并，分别锚定在原文不同位置

## 六、Step 4：P2 产品判词（第三章压力测试人工门；生产期自动化）

### 判断标准

每份专家课分别判断 `WORTH_WRITING` 或 `STOP`：

1. 它是否教给读者一个可以独立带走的认识结构？
2. 内部推理是否真正组织起来，而不是概念堆积？
3. 能否迁移到明显不同于本章的场景？
4. 本章案例是否承担了不可替代的教学作用？
5. 边界和待核验内容是否诚实，没有把未知写成事实？

### 输出

- 每份专家课的 P2 判词
- 进入 Writer 的对象列表（所有通过 P2 的对象，不设固定数量）
- 不进入 Writer 的对象保留为候选池参考

### 停止条件

| 条件 | 动作 |
|---|---|
| 五条验收任一条不通过 | 该对象停止，不进入 Writer |
| 所有对象都失败 | 标记“本章无合适框架”，输出 0 个陪读；开发期等待产品负责人判断 |

第三章压力测试保留 P2 人工。第三章通过后，P2 的五条判断标准转为生产期自动质量门，不再阻塞正式 Skill；通过的对象全部进入 Writer。

---

## 七、Step 5：Writer 编辑

### 输入

- 冻结专家课
- Expert 交接包（承重语义锁 + 锚点 + 待核验清单）
- Writer 风格指南（见 `docs/writer-style-guide.md`）

### 输出

- 每候选一份读者稿（目标 1200-1800 字）
- 编辑台账：保留/删除/重排/术语改写/来源标注折叠 + 理由 + 语义风险评估
- 锚点位置（由 Expert 交接包指定）

### 承重语义锁（全部 HARD）

Writer 不得修改：

1. **核心变量和机制**
2. **因果逻辑方向**
3. **边界条件**
4. **`unknown` 标注**——不得把 unknown 升级为确定事实
5. **学术证据强度**——不得把"本课综合"改成"理论表明"
6. **原文锚点位置**

违反任意一条 = 忠实性检查 FAIL。

### Writer 风格指南 10 条硬约束（HARD）

见 `docs/writer-style-guide.md`。违反任意一条打回重写。

### 推荐结构

```
锚点原文（逐字引用）
  ↓
一句话核心问题（从原文场景引出）
  ↓
框架机制（2-3 段，每段一个论点，每段不超过 3 句话）
  ↓
原文投射（1 段：框架装到本章上，什么变了）
  ↓
跨场景迁移（1 段，≤150 字）
  ↓
**带走什么**（独立成段，视觉突出）
  ↓
边界（1 段，来源标注折叠到括号）
```

## 八、Step 6：忠实性检查

### 输入

- 冻结专家课
- Writer 读者稿
- 承重语义锁

### 输出

- 忠实性报告：列出所有偏离点
- 逐条 PASS/FAIL 判定

### HARD 约束

1. 逐项检查承重语义锁
2. 任何新增变量、机制、边界都视为 FAIL
3. 任何 `unknown` 被升级为确定都视为 FAIL
4. 任何学术证据强度被加强都视为 FAIL
5. 锚点位置偏移视为 FAIL
6. 偏离超过 2 条 → Writer 重写，不改 Expert 课

### 自动放行条件

- 承重语义锁全部通过
- 无新增机制
- 无 unknown 升级
- 锚点位置正确

---

## 九、Step 7：P3 产品判词（第三章压力测试人工门；生产期自动化）

### 判断标准

- 完整阅读体验是否合格
- 多份陪读是否互补，是否信息过载
- 是否有明显阅读体验问题
- 是否接受为产品样张

### 输出

- `ACCEPTED` 或 `REJECTED`（开发期人工判词；生产期由自动检查生成）
- 如果 ACCEPTED，进入装配
- 如果 REJECTED，说明具体原因，返回相应步骤修改

第三章压力测试保留 P3 人工，用于验证阅读体验门是否可靠。第三章通过后，P3 转为自动检查，正式 Skill 不再设置人工门。

---

## 十、Step 8：装配

### 输入

- 原文冻结文本（冻结 EPUB scope）
- 0-N 份通过忠实性检查的 Reader
- 锚点位置

### 装配规则（全部 HARD）

1. 每份 Reader 放在其锚点对应的原文位置之后
2. 保持原文完整，不删原文
3. 多个框架各自独立，不合并
4. 不为它们发明共同的上层框架
5. 锚点位置由 Expert 交接包指定
6. 如果锚点位置无法在原文中匹配，停止并报告

### 确定性收据（HARD）

装配完成后必须生成确定性收据，包含：

- 所有冻结文件的 SHA-256
- 锚点唯一匹配检查
- 原文可逆性检查（移除陪读后逐字恢复原文，SHA-256 校验）
- 装配为确定性操作，没有调用模型

## 十一、停止条件汇总

| 门 | 失败条件 | 动作 |
|---|---|---|
| P1 | 候选判定无法完成或信息相互矛盾 | 标记 `FAILED`；开发期人工介入，生产期按故障策略停止并报告 |
| P1 | 无任何 `WORTH_EXPANDING` | 标记 `NO_FRAMEWORK`，输出 0 个陪读 |
| P2 | 五条验收任一条不通过 | 该对象停止，不进入 Writer |
| P2 | 所有对象都失败 | 标记“本章无合适框架”，输出 0 个陪读；开发期等待产品负责人判断 |
| Writer | 忠实性检查偏离超过 2 条 | Writer 重写，不改 Expert 课 |
| P3 | 阅读体验不达标 | 开发期由产品负责人判断，退回 Writer 或接受；生产期自动退回相应步骤 |
| 装配 | 锚点无法匹配 | 检查原文版本，必要时人工指定 |
| 装配 | 原文不可恢复 | 检查 Reader 是否修改了原文 |

## 十二、错误恢复

| 失败点 | 处理 |
|---|---|
| 比较者阈值判定不合理 | 开发期人工 override，必要时换模型复测 |
| Expert 课通不过 P2 | 停止该对象，保留候选池，不进入 Writer |
| Writer 不忠实 | 返回修改 Writer prompt，不改 Expert 课 |
| 忠实性检查 FAIL | 返回 Writer 修改，或返回 Expert 修正 |
| 锚点无法匹配 | 检查原文版本是否变化，必要时人工指定 |
| 装配不可恢复 | 检查 Reader 是否修改了原文 |

|---|---|---|---|
| H1 | C1-C5 五项检查必须全部显式回答 | HARD | 待确认 |
| H2 | 候选判定理由必须锚定在原文认知增量上 | HARD | 待确认 |

## 十四、成本目标

- 模型调用：按 `N` 和拼接扫描触发情况计算，不设固定次数
- 软上限：3-4 个陪读；超过 4 个提醒阅读负担过重，但不阻断
- 第三章压力测试人工门：2 次（P2 + P3）
- 正式 Skill：0 次人工门，输入章节号后自动输出 0-N 个陪读
- 失败率目标：≤20% 章节需要返工
