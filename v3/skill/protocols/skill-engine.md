# Skill 与工程材料引擎

## 目标

把 Skill、脚本、模板、架构说明、数据流或工程流程转成产品负责人能读懂、能追溯的阅读包。读者先接触净化正文，再由技术负责人页解释机制、取舍和边界；AI 解读不得替代一手主体。

## 输入与逐单元 source map

开始整理前锁定登记过的原始材料。为主读页的每个可见正文单元建立 source map，至少记录：

- 可见单元名称，以及对应的源文件和可定位锚点；
- `保留 / 移动 / 删除` 动作与实际整理方式；
- 合并或重排时涉及的全部来源；
- 重要删除类型、理由及其进入附录、技术负责人页或 audit 的去向。

source map 留在 audit，不把路径、行号和生产状态塞进读者正文。任何无法定位到源材料的句子，或把多个来源合成了新判断的句子，都不是净化正文，必须移到解读层或删除。

## 净化正文边界

正文保留用途、触发条件、用户意图、判断顺序、流程、约束、失败条件、输出要求和源材料已有的设计说明。允许删除、分组、轻量断句和为连续阅读做必要重排，但必须保留一手语气、含义和约束强度，并由 source map 逐单元证明。

命令行噪声、重复执行协议、机器路径、测试日志、审计细节和内部状态编号可移出主读页；关联脚本、模板和参考资料单独标明身份，不得冒充材料主体。AI 的摘要、解释、评价、建议、方法论命名和外部比较不得写进“正文”。

## 两类页面的职责

### 主读页

- 只承担“让读者接触净化后的一手材料”这一任务。
- 只给最小来源身份、净化正文和技术负责人页入口。
- 不提前概括机制，不列资产候选，不把产品解读或技术解读混入正文。

### 技术负责人页

- 不复述主读页，不另写一份换皮摘要。
- 沿一条主线讲清输入如何成为输出，以及关键机制如何约束这条路径。
- 按材料适用性检查状态、分支、权限、外部输入、宿主差异和人工门；不适用时写明依据，不凑栏目。
- 讲清关键取舍及反事实：获得什么、付出什么、不这样做会坏在哪里。
- 讲清失败、拒绝、恢复与停止条件，以及由谁接管。
- 讲清验证证据、可复现范围和迁移边界，再决定是否形成配方或资产卡。

## 3—5 个任务的执行链

标准 Skill 线使用 5 个互相独立的任务，不借用图书角色：

1. **来源整合**：建立净化正文、逐单元 source map、删除记录和关联资产清单。
2. **机制候选**：基于 source map 提交完整机制候选；每个候选只讲一个机制、关键取舍或失败边界，不写最终读者文案。
3. **独立裁判**：核对来源、完整性、认知价值和适用边界；允许 0 条，锁定接受项，生产者不得自评通过。
4. **单一成文**：保持净化正文不变，只把锁定机制写成技术负责人页；不改题、不加料。
5. **独立读者 / 冷启动 / 复现**：先只看最终读者页做阅读体验冷读，再按 manifest 对最终资产执行适用的冷启动或复现；两种结果分开记录。

简单材料可以把来源整合与机制候选合并，或省略不适用的冷启动/复现，降为 3—4 个任务，但生产与独立裁判、成文与独立冷读不得由同一 Agent 自评闭环。需要外部事实时追加共用事实核查角色；若因此突破 5 个任务，必须先说明触发原因并取得用户批准。

机制候选角色负责提交类型化事实核查 request：没有外部事实时明确 `not-applicable`；有任何可见外部事实时，列全非空唯一的 request / claim id、materiality、已有来源与允许取证边界。主控只按该 request 在独立裁判前派发 fact-checker，裁判逐 check id 核对 request claims 精确全覆盖；不得由主控临时猜测核查范围。

## 条件式扩展

- **方法论指认**：只有源机制能支撑“模式—证据—作用—限制”时才写；标签不能替代机制解释。
- **2026 设计评审**：只有登记证据足以支持当前性判断时才写；用户明确要求可以启动取证，不能免除证据要求。必须区分源事实、外部事实和评审判断。
- **外部知识**：只有它会改变机制理解、取舍或迁移边界，或用户明确要求时才启动搜索；写入的事实仍须有可追溯来源。

没有满足启动条件时直接省略，不得为了显得完整或深刻而补齐栏目。

## 复现、冷启动与声明

复现配方或资产卡只在材料证据足以支持时生成。测试前声明对象、profile、输入边界和要验证的链段；测试后记录实际输入、结果、证据和未覆盖项。

资产卡必须独立说明问题、做法、前提、边界、风险和第一步，不依赖内部术语、路径、阶段号或回读源文件。迷你页、浅材料、单张资产卡或局部链段通过，只能证明该对象和该范围；未做完整 source map、完整复现或真实隔离运行时，不得升级为整包、整条 Skill 线或 ReaderLab 流水线通过。

## 即死条件

- AI 摘要或中文转述替代净化正文。
- 可见正文单元没有可定位 source map，或重要删除没有记录。
- 主读页与技术负责人页承担同一任务、互为换皮。
- 只列 happy path，回避适用的状态、权限、人工门、失败、恢复或停止。
- 用方法论标签、时代判断或无关外部知识制造深刻感。
- 未经对应冷启动、复现或真实运行验收就扩大完成声明。
