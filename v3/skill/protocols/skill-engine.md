# Skill 与工程材料引擎

## 目标

把 Skill、脚本、架构说明、数据流或工程流程转成产品负责人能读懂的中文陪读页。读者要先看到净化正文，再看到它解决什么问题、为什么这样设计、技术上难在哪里、能沉淀成什么资产。

## 输入净化

保留：用途、触发条件、用户意图、流程、约束、失败条件、输出要求、设计亮点。

移出正文：命令行噪声、重复执行协议、机器路径、测试日志、审计细节、内部状态编号。移出的内容进入附录、技术解析或 audit，不能冒充正文。

## 输出结构

1. 正文页：净化后的源材料，保留一手语气和关键约束。
2. 产品解读：它在帮用户避免什么成本，为什么不是普通说明书。
3. 技术解读：用非工程师语言讲清机制、数据流、失败边界和取舍。
4. 复用方法：抽出可迁移做法，不直接照搬原项目名。
5. 资产卡：必须能被无上下文 Agent 冷启动使用。

## 技术负责人讲解顺序

1. 机制 walkthrough：从输入到输出，一步步说明系统怎么动。
2. 取舍解释：为什么要这样设计，不这样做会坏在哪里。
3. 方法论指认：指出背后的工程方法，并用人话解释。
4. 2026 设计评审：放到当前 agent workflow、上下文管理、工具调用和验证成本里重新看。
5. 复现配方：给出最小可复用步骤。
6. 资产卡：沉淀为问题、做法、边界、第一步。

## 资产卡冷启动标准

资产卡必须独立解释：

- 问题：它要解决什么。
- 做法：它怎么做。
- 边界：什么时候不能用。
- 第一步：拿到任务后先做什么。

卡内不得出现未解释的内部术语、路径、阶段号或项目暗语。测试发现缺口后必须修订并重测；“通过但带改进项”不算通过。

## 禁止项

- 用摘要替代净化正文。
- 把工程细节写成给程序员看的实现复盘。
- 只说“很复杂”“很高级”，不解释复杂在哪里。
- 把项目内部路径当作资产卡必要前提。
- 未经过冷启动测试就宣称资产卡可复用。
