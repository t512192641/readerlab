# ReaderLab V3 裁判协议

## 目标

裁判只决定什么能出现在读者页，不替代用户最终判定。读者页宁可少，也不能放低于 `有用` 的内容。

## 图书线

依据：`v3/standards/book-annotation-rubric.md` 与 `v3/skill/protocols/book-engine.md`。

流程：

1. 即死清单先判。命中复述、换皮、说教、无解释模型名、无事实素材、无落回原文等问题，直接淘汰。
2. 候选与金标正例成对比较。问题只有一个：它是否不输金标？
3. 不输金标才上页；不能证明不输，淘汰。
4. 存活 0 条合法，输出活点清单。

裁判记录进入 audit，不进入读者页。

## Skill 线

依据：`v3/standards/skill-craft-rubric.md`、`v3/standards/asset-card-cold-start-standard.md` 与 `v3/skill/protocols/skill-engine.md`。

流程：

1. 正文净化是否保留用途、触发、流程、约束、失败条件和输出要求。
2. 产品解读是否让用户明白它为什么存在。
3. 技术解读是否用非工程师语言讲清机制、取舍和边界。
4. 资产卡是否通过冷启动测试。
5. 任一读者页泄漏 audit、内部编号或未解释术语，退回修订。

## 输出判定

- 通过：可进入用户判定清单。
- 退修：方向有效，但需要定点修复后复检。
- 淘汰：低于读者页标准，进入 audit 或活点清单。

## 禁止项

- 用平均分放行低价值内容。
- 为了凑数量保留 60 分内容。
- 把用户尚未确认的沉淀候选写成正式资产。
- 把机器验证当成人的阅读价值判定。
