# ReaderLab V3 独立验收门

## 目标

不同承诺由不同证据主体验收，不能用一个总分互相抵消。裁判不生产内容，不替作者补救，也不替代用户最终体验判定。

## 1. 来源与事实门

- 正文/source map 能定位保留、移动和删除；AI 解释没有冒充一手主体。
- 可见判断中的源内事实能回到原始材料，外部事实能回到本次核实的高可信来源。
- 证据不足或事实冲突会改变结论时，淘汰或停止；不能靠弱化语气放行关键事实。

输出：逐项 `supported | conflicted | insufficient | out_of_scope`，以及整门 `pass | fail | blocked`，附证据位置与受影响内容；来源不可访问或身份不明导致无法判定时，阻塞写在整门状态，不另造逐项枚举。来源证明必须通过；条件事实核查未触发时明确 `not-applicable`，触发时必须覆盖 request 中全部可见事实（无论 materiality）并通过；主控按两子门确定性聚合 `source_and_fact`。

## 2. 绝对价值门

图书候选按 `book-annotation-rubric.md` 判断完整认知是否真正改变原文读法；Skill 单元按 `skill-craft-rubric.md` 判断是否讲清一个关键机制、取舍或失败边界。

- 只问它是否独立达到读者注意力门槛，不问是否“比其他候选更好”。
- 结构完整、表达顺滑、素材丰富或相对第一都不能替代价值。
- `0` 条通过合法；不为填槽位退修低价值候选。

输出：逐项 `accept | reject | blocked`，以及整门 `pass | fail | blocked`；每条只给一个主因和证据。

## 3. 回归门

回归执行者按 `v3/standards/regression-suite.md` 逐 case 读取冻结证据：锁定正例仍接受、硬负例淘汰、待复评/浅材料/局部通过保持原作用域。冲突时停止，不把历史病历改写成作者禁令。

输出：case id、预期、实际、证据、冲突，以及整门 `pass | fail | blocked`。

## 4. 冷读体验门

冷读者只看拟交付读者页，不看候选、评分、实验目的或生产过程。

- 图书：能否一句话复述多知道了什么、它怎样改变原文读法、哪里仍需二次整理。
- Skill：能否区分一手主体与 AI 解读，并说清所读单元的机制、取舍或失败边界。
- “好读”“有认知增量”必须分别记录；表达顺不自动证明价值。

输出：实际复述、费力点、二次整理点和 `not-applicable | pass | fail | blocked`。正文-only 页面为 `not-applicable`；输入污染或测试无效统一记为 `blocked`；用户体验门仍由用户决定。

## 5. 冷启动 / 复现门

- 资产卡冷启动只证明单卡的问题、做法、边界和第一步可独立理解。
- Skill 复现只依赖声明的最终资产，检查适用的状态、分支、权限、人工门、失败、恢复、停止与验证。
- 局部机制片段、迷你页和单卡通过不得升级为完整包复现通过。

输出：输入资产、实际覆盖、缺口、可声称与不可声称，以及 `not-applicable | not-run | pass | fail | blocked`。

## 6. 真实运行完整性门

检查本次 run manifest：模式是否先声明；fresh 是否从原始来源、无生成产物复用且使用全新目录；revision 是否列清复用与实际重跑；样本是否经必要确认；最终声明是否只覆盖实际执行并验收的链段。

内容质量与运行真实性分别判定，互不替代。输出：`pass | fail | blocked` 与逐字段证据。

## 禁止

- 用平均分、相对排名或格式通过放行低价值内容。
- 由同一 Agent 生产候选并自评通过。
- 把机器验证当成人的阅读体验，把用户未确认候选当正式资产。
- 用 revision、局部页、冷启动或复用旧产物声称完整 fresh run 通过。
