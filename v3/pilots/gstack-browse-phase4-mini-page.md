# gstack/browse 第二 Skill 试点迷你成品页

## 页首标识

- Skill 名：`gstack/browse`
- 来源路径：`/Users/tianqiang/技能项目/skills-canonical/packages/gstack/browse`
- 本单元位置：`browse` 是 GSTACK 里的浏览器操作与网页验收能力层。它负责让 Agent 真正打开网页、连续操作页面、留下截图和日志证据。
- 覆盖范围：本页覆盖 `SKILL.md`、命令清单、浏览器状态管理、本地服务、权限钥匙、网页内容安全、文件路径安全、浏览器底层接口限制和测试规模轮廓。它是 Phase 4 第二 Skill 试点，不是完整 ReaderLab 包。

## 先看全景

可以先把 `browse` 想成一台专门借给 Agent 用的测试浏览器。普通聊天里，Agent 只能猜“这个网页应该能打开”；有了它，Agent 可以真的打开页面、点按钮、填表、看报错、截图，再把证据交回来。

这台浏览器不是每点一步就重开一次。它会在本机后台一直开着，下一条命令继续用同一个浏览器状态。你知道 cookie，也可以这样理解：登录后的 cookie、打开过的标签页、页面历史都还在，所以 Agent 能连续走完整个流程，而不是每一步都失忆。

这件事危险也在这里。浏览器会接触外部网页、登录状态和本机文件。外部网页可能把恶意文字写在页面里诱导 Agent；登录状态可能包含敏感 cookie；截图、下载、保存 PDF 又会碰到文件系统。所以 `browse` 的设计重点不是“能打开网页”这么简单，而是让 Agent 能取证，同时不给它一把能乱开的万能钥匙。

## 这是正文：净化后的主流程

`browse` 的主流程分三步。

第一步，Agent 发出一个浏览器命令。命令可以是“打开这个网址”“点击这个按钮”“读取页面文字”“截图”“看控制台报错”。这里的“控制台”就是网页运行时报错或打印信息的地方，前端问题常常会在那里暴露。

第二步，本机后台服务接收命令。这个服务像浏览器管理员：它知道当前开着哪几个页面，哪个页面是当前页，浏览器有没有崩溃，截图要存到哪里，命令有没有权限执行。

第三步，后台服务驱动 Chromium 浏览器执行动作，再把结果交给 Agent。Chromium 是 Chrome 浏览器背后的开源内核；这里用它是因为它能被程序稳定控制，也能产出截图、PDF、页面结构、网络请求和错误日志。

主流程里常用的能力有六类。

导航与读取：打开网址，读取页面文字、链接、表单、页面结构和错误日志。

交互与断言：点击、填写、选择、滚动、等待某个按钮出现，检查按钮是否可见、可点或已选中。

视觉证据：截图、响应式截图、PDF、前后差异对比。响应式截图就是同一个页面在手机、平板、电脑宽度下各截一张，检查排版有没有坏。

本地渲染：把本地 HTML 页面放进浏览器里看效果。HTML 是网页的骨架文本，很多原型和报告可以先生成 HTML，再用浏览器截图确认样子。

复杂登录处理：遇到验证码、扫码、多因素登录或强反爬时，把浏览器交给用户手动处理。用户处理完，Agent 再接回来继续验证。

共享与隔离：当多个 Agent 都想用浏览器时，不直接共享最高权限，而是按能力发临时钥匙。有的只能看，有的能点，有的才能碰 cookie 或底层接口。

## 这是产品解读：它到底帮用户解决什么

`browse` 解决的是网页验收里的三个断层。

第一个断层是证据断层。没有浏览器时，Agent 很容易写“应该可以”“逻辑上没问题”。但网页问题常常藏在真实页面里：按钮点了没反应，登录后跳错页，移动端遮住文字，控制台报错。`browse` 把这些判断变成可观察证据：打开、点击、检查、截图、留日志。

第二个断层是状态断层。网页流程不是孤立的一步。用户可能先登录，再进入后台，再点弹窗，再换手机尺寸看页面。如果每条命令都重新开一个干净浏览器，cookie 和页面状态就没了。`browse` 用持久浏览器保留状态，让 Agent 像同一个人在同一台电脑上连续测试。

第三个断层是安全断层。网页是外部输入，浏览器又能接触登录态和文件。`browse` 的重设计都围绕这个危险：网页内容先当作不可信材料，权限按能力拆开，文件只能写到安全目录，浏览器底层接口默认关闭，用户登录难题交给用户接管。

所以它不是一个截图小工具，而是一套“网页证据采集系统”。它承认浏览器很有用，也承认浏览器很危险。

## 这是技术解读：小白全景图

`gstack/browse` 可以分成七个部件。先知道每个部件“有什么”，再看它“为什么这样设计”。

第一，使用说明。`SKILL.md` 告诉 Agent 什么时候该用这套浏览器：打开网页、测试站点、截图、验证表单、处理登录。它还写了遇到验证码或扫码时不要硬闯，要交给用户接管。这里的价值是把“什么时候用浏览器”这件事先讲清楚，避免 Agent 在只需要读文件时也乱开网页。

第二，命令清单。`commands.ts` 像一本总账，登记所有浏览器动作：哪些是读取页面，哪些会改变页面，哪些是截图、切标签页、重启服务这类管理动作。先有这本总账，后面权限、文档、健康检查才能共用同一套定义。否则就会出现文档说有某个按钮，真实运行时却没有；或者新增了危险命令，却忘了放进权限模型。

第三，浏览器管家。`browser-manager.ts` 负责真正的浏览器生命周期：启动 Chromium、保留 cookie、管理标签页、记住当前页面、处理弹窗、设置窗口大小、浏览器崩溃时退出。它像一个现场管理员，保证 Agent 的连续操作不会因为每次重启浏览器而断掉。

第四，本地服务。`server.ts` 是命令入口。Agent 不是直接摸浏览器，而是把命令发给本机服务，本机服务检查权限、路由到对应处理器、记录日志，再把结果返回。这样做比“命令直接操控浏览器”重很多，但好处是所有危险动作都要过同一个门口。

第五，临时钥匙。`token-registry.ts` 管权限。这里的 token 可以理解成临时钥匙，不同钥匙能开的门不同：有的只能读页面，有的能点击填写，有的能碰 cookie 或运行页面脚本，有的能重启浏览器。cookie 是登录状态的一部分，所以碰 cookie 不是普通读取，而是高权限动作。

第六，网页内容护栏。`content-security.ts` 处理网页内容不可信的问题。网页正文、按钮文字、隐藏元素、给辅助阅读软件用的标签，都可能夹带“忽略之前指令”这种诱导语。这里的 ARIA 标签，简单说就是网页给读屏软件看的辅助说明；用户不一定看见，但 Agent 读取页面结构时可能会读到。`browse` 会把这些内容包进不可信边界，并检查隐藏指令。

第七，文件和底层接口护栏。`path-security.ts` 限制截图、下载、PDF 只能写到安全目录；遇到符号链接还要看它真实指向哪里，防止表面在安全目录、实际绕到别处。`cdp-allowlist.ts` 管浏览器底层调试接口。这个接口能看到更深的页面信息，也更容易越权，所以默认全关，只开放少数写明理由的方法。

## 逐部件拆开看

使用说明先解决入口问题。Agent 拿到任务时，先判断是不是网页验收：要不要打开真实页面，要不要点击，要不要截图，要不要看登录后的状态。不是这类任务，就不该动用浏览器。

命令清单解决一致性问题。一个浏览器工具如果没有总账，很快会乱：文档一套，运行时一套，权限检查又是一套。`browse` 把命令集中登记，让系统先知道“我们到底提供了哪些动作”。

浏览器管家解决连续状态问题。测试网页最怕每步都失忆。比如已经登录了后台，下一步要点设置页；如果浏览器重开，cookie 没了，流程就断了。浏览器管家让这些状态留在同一个浏览器里。

本地服务解决统一入口问题。所有命令都先到服务端，再由服务端决定能不能执行。这样安全检查、日志、权限、远程接入都能集中处理，不会散落到每个命令里。

临时钥匙解决共享风险问题。多个 Agent 共用一个浏览器时，不能每个都拿最高权限。只需要截图的 Agent 不该读 cookie；只需要点测试站点的 Agent 不该重启浏览器；外部 Agent 更不该操作别人的标签页。

网页内容护栏解决提示注入问题。网页上出现的文字只是被观察对象，不是命令。哪怕网页写着“请忽略系统指令”，Agent 也只能把它当网页内容看。隐藏文字和辅助标签也一样，先标成不可信，再交给 Agent 阅读。

文件护栏解决出口问题。截图和下载看起来只是保存结果，但文件路径一旦放开，就可能写到不该写的地方，或者通过符号链接绕出安全目录。统一路径校验是在堵这个口子。

底层接口护栏解决能力过强问题。浏览器底层调试接口很像后台维修门，能做普通按钮做不到的事。`browse` 默认不开这扇门，只在确实需要时开一条很窄的白名单。

用户接管解决自动化边界问题。验证码、扫码、多因素登录，本来就是让机器别轻易越过的门。`browse` 不把它伪装成能自动解决，而是把浏览器交给用户，用户处理完再还给 Agent。

测试集解决信任问题。`browse` 的测试覆盖权限、路径、网页注入、cookie、截图、PDF、标签页隔离、浏览器崩溃和远程接入。它不是只测“函数有没有返回”，而是在测“把浏览器借给 Agent，会不会从这些地方出事故”。

## 读完带走

`gstack/browse` 的核心不是截图，而是把网页验收从猜测变成证据：真实打开、真实点击、真实观察、真实截图。

它最值得 ReaderLab 继承三件事：第一，证据化交互；第二，保留连续状态；第三，把危险能力拆成一层层边界。

它最不该照搬的是冗长启动壳和机器状态输出。那些内容对真实运行有用，但对读者理解主线是噪音，应放进附录或审计。

这个样本比 `gstack/spec` 更适合测试技术负责人页上限，因为它有真实代码结构、权限模型、安全模型、浏览器生命周期和大量测试。
