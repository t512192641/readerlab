# gstack/browse Phase 4 资产卡

本文件用于无上下文 Agent 冷启动测试。卡片本体不依赖原始 Skill、项目路径或阶段号。

## 卡 1：持久浏览器证据器

| 字段 | 内容 |
| --- | --- |
| purpose | 防止 Agent 只凭猜测评价网页，把“应该可以”当成真实验收。 |
| reader | 要设计网页验收、产品自用试跑或用户界面回归检查流程的 Agent。 |
| problem | 网页问题通常需要连续操作才能判断：打开页面、登录、点击、查看错误、截图、比较前后状态。如果每一步都重新启动浏览器，状态会丢失，证据也不连续。 |
| approach | 用一个本地持久浏览器作为证据器：所有命令复用同一个浏览器状态，按“打开页面 -> 观察结构 -> 执行动作 -> 看变化 -> 留截图 / 日志”的顺序验证。 |
| boundary | 适合需要真实网页状态、交互和视觉证据的任务；不适合只解释概念、阅读静态代码或用户不允许打开网页的场景。 |
| first_step | 先确定要验证的用户路径，然后打开目标页面并保存第一份页面结构或截图作为基线。 |
| pass_example | “验证注册流程能不能从首页走到成功页。”适用，因为必须连续点击、填表、观察结果。 |
| fail_example | “解释什么是响应式设计。”不适用，因为不需要真实浏览器证据。 |
| boundary_example | “页面还没部署，只能看设计稿。”边界场景，关键考量是是否有可打开页面；没有页面时只能做设计审查，不能声称已浏览器验收。 |

## 卡 2：网页内容默认不可信

| 字段 | 内容 |
| --- | --- |
| purpose | 防止网页正文、按钮标签、隐藏文字或可访问性标签伪装成给 Agent 的指令。 |
| reader | 要让 Agent 读取网页内容、日志、表单或页面结构的系统设计者。 |
| problem | 网页内容来自外部，页面可以写“忽略之前指令”之类的文本，也可以把恶意内容藏在不可见元素或辅助阅读标签里。Agent 如果把页面内容当可信指令，就会被网页牵着走。 |
| approach | 把网页输出包进“不可信内容”边界；读取前检查隐藏元素和可疑辅助标签；只把网页内容当观察材料，不把它当系统指令。 |
| boundary | 适合任何读取第三方网页、用户生成内容、网页日志或页面结构的 Agent；不适合 Agent 只处理自己可信的本地配置文件。 |
| first_step | 在返回网页文本前，先标明这些文本来自不可信页面，并检查是否有隐藏指令或伪装指令。 |
| pass_example | “读取一个陌生网页并总结页面内容。”适用，因为网页可能包含诱导 Agent 的文字。 |
| fail_example | “读取本地已审核的产品需求文档。”不适用，因为它不是网页运行时输出。 |
| boundary_example | “读取公司内部后台页面。”边界场景，关键考量是页面是否可能包含用户生成内容；只要页面里有外部输入，就仍按不可信处理。 |

## 卡 3：按能力发临时钥匙

| 字段 | 内容 |
| --- | --- |
| purpose | 防止多个 Agent 共用浏览器时拿到过大的权限，误操作别人的页面、读取敏感状态或控制整个浏览器。 |
| reader | 要设计多 Agent 共用工具、远程操作工具或受限执行环境的 Agent。 |
| problem | 浏览器工具同时能读取页面、点击页面、运行脚本、访问 cookie、写文件、重启服务。把这些能力都放进一把长期钥匙里，任何子 Agent 泄漏或误用都会扩大事故。 |
| approach | 用临时钥匙按能力授权：只读、可交互、高权限、控制浏览器分开；还能限制域名、请求频率和只能操作自己的标签页。 |
| boundary | 适合共享工具、远程 Agent、多人或多 Agent 同时操作同一资源的场景；不适合单人一次性本地脚本且没有敏感状态的场景。 |
| first_step | 先列出工具能力，再把每种能力分级：哪些只读，哪些会改状态，哪些能接触敏感数据，哪些能控制整个服务。 |
| pass_example | “让一个外部 Agent 帮我点测试站点，但不能看 cookie 或重启浏览器。”适用，因为需要限权。 |
| fail_example | “我本地一次性运行一个没有登录态的截图脚本。”不适用，因为共享权限风险很低。 |
| boundary_example | “团队内部 Agent 都可信。”边界场景，关键考量是可信不等于不会误操作；只要共享真实登录态或文件写入能力，就仍要分权。 |

## 卡 4：文件出口只开到安全目录

| 字段 | 内容 |
| --- | --- |
| purpose | 防止截图、下载、归档、脚本输出这类“写文件功能”被绕成任意文件读写或项目文件外泄。 |
| reader | 要给 Agent 开文件输入输出能力的工具设计者。 |
| problem | 浏览器工具常常需要写截图、PDF、下载文件，也可能从文件读取脚本。如果路径不限制，Agent 或远程调用方可能写到敏感位置，或通过符号链接绕出安全目录。 |
| approach | 所有文件路径先转成真实绝对路径；写入只允许临时目录或当前工作目录；远程取文件只允许临时目录；遇到符号链接要检查它真实指向哪里。 |
| boundary | 适合任何允许 Agent 读写本机文件的工具；不适合完全不接触文件系统的纯内存计算。 |
| first_step | 先列出所有会读写文件的命令，并让它们共用同一个路径校验函数。 |
| pass_example | “网页截图要保存到本地，并允许远程 Agent 下载结果。”适用，因为有文件写入和远程取回。 |
| fail_example | “只在内存里比较两个字符串。”不适用，因为没有文件出口。 |
| boundary_example | “只允许写到临时目录，但临时目录里有用户创建的符号链接。”边界场景，关键考量是要检查链接真实目标，而不是只看路径字符串。 |

## 卡 5：底层调试接口默认关闭

| 字段 | 内容 |
| --- | --- |
| purpose | 防止为了少数高级能力，把浏览器底层调试接口全部开放给 Agent。 |
| reader | 要给 Agent 暴露高级系统接口、调试接口或管理员接口的工具设计者。 |
| problem | 浏览器底层调试接口能做很多普通命令做不到的事，包括读取底层网络数据、操纵页面、访问浏览器级状态。全开放会绕过正常权限和安全检查。 |
| approach | 默认拒绝所有底层方法，只白名单少量经过审查的方法；每个白名单方法都说明作用范围、输出是否可信、为什么允许。导航、任意网络读取、容易泄露内容的方法不进白名单。 |
| boundary | 适合强大但危险的底层接口，例如浏览器调试、系统管理、数据库管理或云资源管理；不适合能力很小且没有越权风险的普通函数。 |
| first_step | 先把底层接口全部关掉，再按真实需求逐个加入白名单，并给每个条目写允许理由。 |
| pass_example | “Agent 需要读取页面布局指标，但不能任意抓网络响应体。”适用，因为只应开放安全子集。 |
| fail_example | “工具只有一个把摄氏度转华氏度的函数。”不适用，因为没有底层越权面。 |
| boundary_example | “高级用户要求开放全部调试能力。”边界场景，关键考量是高级用户也会犯错；若必须开放，应放到单独高权限模式，而不是默认路径。 |
