- 每卡演练三场景：明确适用、明确不适用、边界场景。

## 卡 2 复测摘要

测试 Agent 能说清：

- 问题：技术问题常能从项目证据里先回答一半，不能让用户替 Agent 定位上下文。
- 做法：先读入口文件、相关实现或配置、现状测试 / 输出 / 文档，再只问证据回答不了的问题。
- 边界：适合已有项目里的功能、bug、重构、架构和测试任务；不适合没有项目材料的纯概念讨论。
- 第一步：先找入口、相关实现 / 配置、现状证据三类材料。

三场景判断：

- 适用：`生成脚本没有产出 manifest`，因为应先看生成入口、manifest 相关逻辑、最近输出或测试。
- 不适用：`什么是 manifest`，因为这是概念解释，不需要项目证据。
- 边界：`给一个新项目设计 manifest`，关键是判断是否已有仓库和约束；有则读证据，没有则声明绿地并问产品约束。

## 卡 3 复测摘要

测试 Agent 能说清：

- 问题：发出去、存起来或交给新 Agent 的材料会扩大传播，脏工作区会污染新执行者。
- 做法：对即将送出的精确文本做出口扫描；派生执行 Agent 前检查工作区状态。
- 边界：适合公开 issue、共享文档、长期归档、发给新 Agent；不适合当前对话里临时讨论且不落盘的草稿。
- 第一步：先扫描精确文本，再检查工作区状态。

三场景判断：

- 适用：`把这段任务发成 GitHub issue，并让另一个 Agent 开工`，因为材料离开对话且会派生执行。
- 不适用：`当前对话里临时想几个标题，不保存`，因为没有出口。
- 边界：`把草稿存到本地私人 notes，稍后再看`，关键是是否长期保存、是否可能同步、是否含敏感内容。
