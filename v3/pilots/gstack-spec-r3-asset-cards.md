# gstack/spec R3 资产卡冷启动测试输入

本文件是冷启动测试给无上下文 Agent 的唯一材料。测试记录另存 `v3/pilots/gstack-spec-r3-cold-start-test.md`。

## 卡 1：五问锁 Why 门

| 字段 | 内容 |
| --- | --- |
| purpose | 防止 Agent 把一句模糊愿望直接包装成貌似完整的任务。 |
| reader | 要设计需求澄清流程、但不了解原始 Skill 的 Agent。 |
| problem | 用户已经想把事情放进待办或开发队列，但这件事还缺少受影响对象、现状、目标、时机和验收标准。 |
| approach | 先锁五问：谁受影响、现在发生什么、应该怎样、为什么现在做、怎样算完成。五问没有闭合，不进入方案设计。 |
| boundary | 适合“想进入执行但还说不清”的任务；不适合闲聊、纯探索、灵感收集，或用户尚未决定是否要做的想法。 |
| first_step | 直接问五问，并把缺失项标出来。 |
| pass_example | “把阅读包体验优化一下，先建个任务。”适用，因为缺少对象、现状、目标、时机和验收。 |
| fail_example | “我还在想要不要做阅读包，你陪我聊聊方向。”不适用，因为它还处在探索阶段。 |
| boundary_example | “我们大概知道要修阅读包导读，但验收还没想好。”边界场景，关键考量是目标已有，但完成标准缺失；先补验收再进入方案。 |

## 卡 2：读证据后再问技术问题

| 字段 | 内容 |
| --- | --- |
| purpose | 防止 Agent 用通用问题轰炸用户，让用户替它定位项目上下文。 |
| reader | 要把项目内功能、bug、重构或架构任务写清楚的新 Agent。 |
| problem | 技术问题常常能从项目证据里先回答一半；如果 Agent 不先读证据，问题会空泛，任务会缺少已验证现状。 |
| approach | 问技术问题前，先读最小证据包：一个入口文件、一个直接相关实现或配置、一个能说明现状的测试 / 输出 / 文档。读不到时，明确说搜索了什么、没找到什么。 |
| boundary | 适合已有项目里的功能、bug、重构、架构和测试任务；不适合完全没有项目材料的纯概念讨论。 |
| first_step | 先找入口、相关实现 / 配置、现状证据三类材料；只问这些证据无法回答的问题。 |
| evidence_enough_rule | 至少能回答“当前入口在哪里”“相关行为由谁负责”“有什么证据说明现在怎样”。答不上来就继续读，不急着问用户。 |
| pass_example | “生成脚本没有产出 manifest。”适用，先看生成入口、manifest 相关逻辑、最近输出或测试。 |
| fail_example | “什么是 manifest？”不适用，这只是概念解释，不需要项目证据。 |
| boundary_example | “我们要给一个新项目设计 manifest。”边界场景，关键考量是是否已有仓库和约束；有则读证据，没有则声明绿地并问产品约束。 |

## 卡 3：出口扫描与执行前保护现场

| 字段 | 内容 |
| --- | --- |
| purpose | 防止要发出去、存起来或交给新 Agent 的任务材料泄露敏感内容，或让新 Agent 基于半成品工作区开工。 |
| reader | 要发布任务、归档任务或派生执行 Agent 的调度 Agent。 |
| problem | 草稿一旦进入 issue、归档、共享文件或新 Agent，就可能扩大传播；如果当前工作区还有未提交改动，新 Agent 也可能基于不稳定现场工作。 |
| approach | 对即将送出的精确文本做出口扫描；如果要派生执行 Agent，再检查当前工作区是否有未提交修改，并决定继续、暂存或取消。 |
| boundary | 适合任何会离开当前对话的材料：公开 issue、共享文档、长期归档、发给新 Agent；不适合只在当前对话里临时讨论且不落盘的草稿。 |
| first_step | 先扫描精确文本，再检查工作区状态。 |
| scan_checklist | 检查密钥 / token、个人信息、真实人名绑定负面判断、客户或供应商负面事件、未公开策略、保密协议材料、内部路径或代号、未经确认的半成品结论。 |
| pass_example | “把这段任务发成 GitHub issue，并让另一个 Agent 开工。”适用，因为材料要离开对话且会派生执行。 |
| fail_example | “我在当前对话里临时想几个标题，不保存。”不适用，因为没有出口。 |
| boundary_example | “把草稿存到本地私人 notes，稍后再看。”边界场景，关键考量是是否长期保存、是否可能同步、是否含敏感内容；若会同步或长期保存，就扫描。 |
