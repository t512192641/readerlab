# v0.2 方法与配置

## 路径选择

采用 **路径 B**。v0.1 的可读输入清单和席位图记录了章节、席位和字节身份，但没有记录可恢复的模型名称、推理强度、运行方式或其他足以证明调用等价的配置。因此不把新普通组与 v0.1 五席写成严格匹配对照；本轮同时新运行五个普通独立 Agent 和五个专业席位 Agent，十次使用完全相同的当前默认模型与推理配置。

## 当前配置记录

- 模型部署别名：`unknown`；由当前 Codex 宿主默认继承，主控未暴露精确别名。
- 推理强度：`unknown`；十次调用均不单独覆盖，继承同一当前默认设置。
- 运行方式：十个 fresh-context sub-agent 调用；每个调用只收到白名单输入，自己只写一个 raw 输出路径。
- 语义调用总数：普通 5 + 专业 5 = 10。第一阶段门槛复核是独立控制调用，不计入两组样本。
- 外部搜索：0；Expert／Writer／Reader：0。

## 共同输入身份

- 章节路径：`docs/expert-teaching-v0.1.2-migration-inputs/A/source.xhtml`
- 原始字节数：34,512
- SHA-256：`0f4af98ac9beb82cea8d4ad708191bf28aa7758645249e0640d6c1d9d5c4f88a`
- 所有 Agent 读取完整章节，不使用作者观点摘要、整书背景或 v0.1 输出。

## 唯一处理差异

- 普通组：共同任务 + 完整章节；不带学科、人物、图书、固定专家或跨领域组合。
- 专业组：共同任务 + 完整章节 + 一个唯一席位方向卡；席位方向只作为知识库存起点，不预指定答案。
- 两组：相同字段、相同 0—2 条上限、相同结果等级枚举、相同“不得自评 A/B/C”约束。

## 隔离边界

每次调用的 prompt 只列出章节、共同任务、（专业组）自己的席位卡和自己的输出路径。Agent 被明确禁止搜索、列目录、读取其他 run、v0.1 Expert/最终报告或组间结果。该机制提供功能性上下文隔离与可审计白名单，不声称 OS/container 安全隔离。

## 失败与重试

调用失败只能重试同一个运行编号；失败消息、重试次数和最终 raw 状态必须写入 run ledger 或 manifest。不得删除失败样本或用成功样本替代固定调用数。
