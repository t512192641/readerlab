# Phase 4 正式试点闸门

Phase 4 是两条完整成品阅读包的真实试点，不是新的校准批次，也不恢复旧 Python / validator 线。用户验收阅读体验；审计层保存来源、筛选和测试证据。未经用户确认，任何沉淀候选不得写入 LifeAtlas 正式登记簿。

## 共用边界与运行规则

- 只在本 worktree 的 `v3/` 内产出试点包和 audit；不改写书籍源文件，不改动 gstack 源仓库。
- 读者页只出现可读正文、陪读内容和沉淀候选。来源地图、素材卡、候选淘汰、裁判记录、评分、提示词、路径细节和测试日志一律留在 audit。
- `gstack/spec` 是 Phase 1 的校准与资产卡冷启动基线；Phase 4 的 Skill 对象固定为 `gstack/browse`。
- 同一条线最多运行三轮成品装配与验收修订。第三轮后仍不能过门，停止补丁式迭代，归档证据并报告阻塞、失败条件和下一步决策。
- 事实必须能追溯到源材料或已核实的外部资料。发现事实错误时，先撤下或改正受影响的读者内容，在 audit 记录来源、影响范围和修订，再重过该内容所属的体验与质量门；不得把“待核实”伪装成确定事实。

## 图书线：`022_丰饶时代`

### 输入边界

- 输入是该章节的一手正文和最小必要的章节定位信息。
- 旧版通用 `> 陪读` 块、既有 AI 批注、评分和审计文本都不是正文，也不得作为批注锚点。
- 允许轻量清理空格、空行和断行；不得压缩、改写或以导读替代正文。

### 读者页必须交付

- 一页 Obsidian 可读 Markdown：章节标题、净化正文、通过死刑制的页边批注（可为 0 条）、章末延伸讲堂、沉淀候选区。
- 0 条页边批注合法；章末延伸讲堂不可省略，且必须是连贯讲解，不是活点清单、素材索引或字段表。
- 读者页禁止生产词、协议词、评分、审计说明和机器过程。正文与讲堂体不得中英混杂、堆素材或使用“落回原文”等宣告式收尾。

### audit 必须保留

- 正文净化记录与来源地图，能定位每段正文和每个批注锚点来自原章节的哪里。
- 活点、素材卡、候选批注、金标成对比较与淘汰理由；素材卡须保留事实、连接和置信度。
- 讲堂体所用外部事实的来源和核验结果，以及事实修订记录。
- 每轮读者体验反馈、对应改动和是否过门的结论。

### 通过闸门

- 用户能把它当真实阅读页连续读完：正文没有被陪读取代，讲堂带来非摘要型认知增量，读者页没有审计泄漏。
- 每条可见页边批注都经死刑制放行；没有存活批注时，页面仍以正文与讲堂体构成完整阅读体验。
- 任何外部事实能从 audit 追到来源；发现错误后的修订必须重新通过本节闸门。
- 使用相同章节源、固定的 V3 协议和范例库，可由另一执行者复现同样的包结构、净化边界、audit 字段和放行规则；不要求复现措辞或批注数量。

## Skill 线：`gstack/browse`

### 输入边界

- 输入是 `gstack/browse` 的源 Skill、与其直接相关的真实脚本、架构和数据流证据。
- 不把 `gstack/spec` 的阶段、复现清单或叙述混入 `browse`；它只可作为校准与资产卡冷启动基线。
- 源仓库不改动。命令行噪声、机器路径、重复执行外壳、测试日志和内部状态编号移到附录、技术解读或 audit。

### 读者页必须交付

- 主读页：先给净化正文，保留用途、触发条件、用户意图、流程、约束、失败条件、输出要求和设计亮点。
- 产品解读：说明它替用户避免什么成本，不能重述正文或写成宣传语。
- 技术负责人页：先给只认识 cookie 的读者也能跟上的全景，再逐部件按“先有啥、再为什么”讲机制、数据流、取舍和失败边界。
- 资产卡与沉淀候选区：资产卡独立可读，候选不写入正式登记簿。
- 可以有来源地图，但只放 audit；读者页不写成逐文件导读或路径清单。

### audit 必须保留

- 源快照或稳定来源定位，以及机制、脚本、架构与数据流的来源地图。
- 正文剥离清单：每类被移出内容、原因和去向。
- 技术解读的关键机制证据、取舍证据和事实核验记录。
- 每张资产卡的无上下文冷启动测试：只给卡片，禁止读源文件和搜索；完整复述问题、做法、边界、第一步，并完成适用、不适用和边界三场景演练。
- 复现演练：另一执行者只依赖净化正文、技术负责人页与资产卡，说明该 Skill 的问题、核心做法、关键边界和第一步；记录其无法复现或误解的点。
- 每轮读者体验反馈、改动和是否过门的结论。

### 通过闸门

- 用户对主读页能看懂它怎么运作；对产品解读能明白为什么这样设计；对技术负责人页能学到可迁移的机制，而非只认识术语。
- 资产卡全部通过冷启动标准；“通过但带改进项”不算通过，修订后必须重测。
- 复现演练能说清问题、核心做法、关键边界与第一步，并能正确区分至少一个适用与一个不适用场景；否则退回修订。
- 读者页不泄漏内部路径、阶段号、audit 或未解释的工程黑话。任何事实错误修订后必须重过体验、冷启动或复现中受影响的门。

## 试点关闭条件

- 两条线都交付完整读者页与对应 audit，并通过各自的体验、复现和冷启动闸门。
- 用户对两个成品包给出明确的阅读体验结论；这不是校准表，也不由机器评分替代。
- 所有未通过项、事实错误和第三轮止损项都有可追溯记录。只有满足这些条件，才可讨论进入 Phase 5 的用户确认回写。
