# Phase 4 真实试点闸门

本文件只在设计或执行 Phase 4 fresh / revision 试点时读取，不在 V3 默认启动链。Phase 4 验证真实成品与运行真实性；不恢复旧 Python / validator 线，不自动进入 Phase 5 或写回 LifeAtlas。

## 开跑前闸门

1. 从 `v3/skill/templates/run-manifest.md` 建立本次 manifest，先声明 `fresh | revision`。
2. 核对原始来源、指纹、实际读取范围、样本依据、任务上限和全新隔离输出目录。
3. 若样本选择会实质影响流程能力结论，先向用户提交候选、差异和推荐理由；确认前停止。
4. 任务已由当前权威文件或用户固定时，不得换成更容易的小切片。

## 运行真实性

### Fresh run

- 从原始章节或源 Skill、脚本、模板、架构和直接证据开始。
- 重新执行正文/source map、锚点或机制识别、候选、核查、裁判、装配和声明范围内的验收。
- 不复用旧净化正文、reader page、audit、source map、素材卡、候选、裁判、资产卡或复现结果。
- 使用唯一 run id 的新目录；`reused_generated_artifacts: none`。旧来源 URL 只能作线索，本次重新核实。

### Revision run

- 可复用明确基线，但 manifest 必须逐项记录复用、改动、实际重跑、未重跑和不可声称范围。
- 只验证局部修订；不得声称完整流程从原始材料真实跑通。

失败产物留在本次目录并标状态，不覆盖、混写或回填上一轮。内容质量与运行真实性分别验收。

## 共用读者与证据边界

- 读者页只出现一手主体和通过独立门的读者内容；source map、候选、事实核查、裁判、评分、运行和复用证据留在 audit。
- 事实必须回到原始材料或本次核实的高可信来源。错误影响哪个可见判断，就撤下并重过对应事实、价值和体验门。
- 同一条线最多三轮成品装配与用户验收修订；第三轮仍失败则停止补丁式迭代。
- 完成报告逐段列输入、实际执行、验证、复用、未执行、失败和待用户体验验收；只声明实际通过的链段。

## 图书线：`022_丰饶时代`

### 固定输入

- 输入是该章节的一手正文与最小定位信息；允许轻量清理，不压缩、不改写、不用导读替代正文。
- 旧 `> 陪读` 块、既有 AI 批注、评分、audit 和旧成品不是正文，也不能作为 fresh 的锚点或输入。

### 读者页

- 一页 Obsidian 可读 Markdown，完整正文优先。
- 陪读单元为 0 个或多个；每个只完成一个认知任务，并已通过事实、绝对价值和冷读门。
- 0 条合法；不得用“每章至少一段”、固定字数、固定结构或相对最好逼迫上页。
- 不出现候选、素材卡、裁判、金标、run manifest、评分或审计说明。

### audit

- 本次 manifest、原始来源指纹、正文清理和逐段 source map。
- 独立锚点提名、归并、完整认知候选、盲区审计、事实核查和绝对裁判。
- 锁定观点、禁止枝节、成文交接、冷读复述和用户体验反馈。
- 每项可见判断的来源、事实修订与受影响范围。

### 通过

- source map 证明正文未被 AI 替代。
- 每个陪读单元让冷读者说出新增认知和改变的原文读法，不需整理新增材料。
- 硬负例仍被淘汰，锁定正例仍接受；0 条时如实报告，不算自动失败或成功。
- 用户明确通过真实阅读体验；机器、裁判或冷读不能代替用户。

## Skill 线：`gstack/browse`

### 固定输入

- 输入是源 Skill 及直接相关的真实脚本、模板、架构和数据流证据；源仓库只读。
- `gstack/spec` 只保留 Phase 1 校准与资产卡冷启动作用域，不得混入 `browse` 机制或冒充 Phase 4 完整试点。

### 读者页

- 主读页先给可追溯净化正文；AI 总结、评价和建议不得混入正文。
- 产品解读只说明问题与成本；技术负责人页只讲机制、取舍、失败、恢复、停止、验证和迁移边界，不做换皮摘要。
- 方法论指认、时代评审和外部知识只有源证据成立或用户明确要求时出现。
- 资产卡独立可读；沉淀仍是候选，未经用户确认不写回。

### audit

- 本次 manifest、源指纹、实际读取范围、逐单元 source map 和删除类型/去向。
- 对状态、分支、权限、人工门、失败、恢复、停止和验证的适用/不适用判定及源证据。
- 关键机制与取舍的反事实证据；事实核查、冷读和用户反馈。
- 资产卡冷启动与完整复现分开记录；输入资产、实际覆盖、缺口和声明范围清楚。

### 通过

- 用户能区分一手主体与 AI 解读，并理解系统怎样工作、关键门为何存在、失败时怎样停止或恢复。
- 资产卡逐卡通过冷启动；“通过但带改进项”须修订重测。
- 完整复现者只依赖声明的最终资产，覆盖适用的状态、权限、人工门、失败、恢复、停止和验证。
- 迷你页、单卡或局部机制通过不等于 `gstack/browse` 完整包通过。

## Phase 4 关闭

- 两条线分别完成真实 manifest、隔离输出、读者页、audit 和适用的独立验收。
- 用户分别给出明确体验结论；所有失败、事实修订和第三轮止损可追溯。
- 只有同时满足以上条件，才可讨论 Phase 5；任何单线、局部或 revision 结果不得扩大为整个 Phase 4 或 V3 通过。
