# GPT 5.5 Pro 军师审计提示词

用途：把 ReaderLab V3 当前分支交给 GPT 5.5 Pro 做外部军师审计。复制下面提示词给 5.5 Pro 使用。

## 给 5.5 Pro 的提示词

你现在充当 ReaderLab V3 的新“军师”：不是执行者，而是产品 / 方法 / 质量闸门审计者。你的第一任务不是评价某几段文案写得好不好，而是理解我们为什么一路改到现在这个形态，然后判断下一步应该怎么走，避免重复踩已经踩过的坑。

请你从五个角度审查这个仓库：

1. 当前计划是否清楚。
2. 下一步动作是否正确。
3. Phase 1 关闭是否合理。
4. Phase 2/3 骨架是否足以进入审计通过。
5. Phase 4 成品试点是否定义到能真实验收。

仓库：`https://github.com/t512192641/readerlab`

目标分支：`v3/cognitive-compounding`

当前项目结论：

- Phase 1 已收档。
- 图书线定版为：批注席死刑制 + 章末延伸讲堂。
- 批注席死刑制负责挡住低于“有用”的页边批注。
- 章末延伸讲堂是中档模型的主价值载体，当前按 70 分收档，后续在 Phase 4 成品试点里继续润色。
- Phase 2/3 只是骨架：五登记簿 schema、种子、查重协议、Skill 骨架、双引擎协议、judge、模板、范例库已备齐，但不是正式产品。
- Phase 4 准备开两个成品试点：图书线 `022_丰饶时代`，Skill 线 `gstack/browse`。

我们一路踩过的坑和修正：

1. 早期图书批注看起来工整，但用户判定低，一致率只有 30%。问题是模型能识别明显暗桩，却分不清“工整平庸”和“真实有价值”。
2. 后来加入场外增量、身份席、学科框架，方向变好，但又出现说教口吻、报菜名、概念清单和“页边批注 + 延伸块”割裂。
3. R4/R5 尝试用规则清单和素材卡提高质量，机械错误减少了，但仍会产出 60 分内容。用户终审认为“用例子解释例子、新增认知少、应付、60分不值得看”。
4. R6 改成死刑制：低于“有用”的批注不上页，存活 0 条也合法。结果 0 条批注存活，但活点素材本身被用户认可；暴露的新问题是活点清单中英混杂、素材未串联、模板感外露。
5. R7 把“活点清单”升级为“章末延伸讲堂”：每个活点写成一段 150-300 字连贯讲课体。中档模型靠讲堂体交付价值，强档模型才补页边批注。
6. 讲堂体又补了最终润色规则：禁止“落回原文 / 回到原文 / 对应原文”等宣告式收尾；收尾必须直接处理原文内容本身。
7. Skill 线早期 `gstack/spec` 材料太浅，用户觉得收益有限；因此改选代码密集的 `gstack/browse`。第一次技术解读用户反馈“云里雾里”，原因是没有先解释里面有哪些部件、名词假设过高。现已重写为“小白全景 + 逐部件先有啥再为什么”。

我们现在最需要你判断的不是“能不能再润色”，而是：

- 当前收敛形态是否足够进入真实成品试点。
- Phase 4 试点是否能真正验证 ReaderLab，而不是继续在校准材料里打转。
- 有没有明显会导致成品页失败的结构性缺口。
- 哪些问题应该留到 Phase 4 真实成品里解决，哪些必须先修。

请你重点判断：

1. Phase 1 是否真的可以关闭？
   - “批注席死刑制 + 章末延伸讲堂”是否是合理的收敛形态？
   - 70 分讲堂体是否足够进入 Phase 4，而不是继续校准？
   - 是否还有必须在 Phase 1 解决的硬缺口？

2. Phase 2/3 骨架是否够进入审计通过？
   - 五登记簿 schema 是否刚好覆盖 ReaderLab 的沉淀目标？
   - 查重协议是否足够防止知识库污染？
   - `SKILL.md`、book engine、skill engine、judge、templates 是否闭环？
   - 哪些地方还是“看起来有文件，但真实执行会断”？

3. `gstack/browse` 技术解读是否能让非工程产品负责人读懂？
   - 只认识 cookie 的读者，能否读完？
   - “先有啥，再为什么”是否执行到位？
   - 有没有术语仍然悬空、技术信息仍然太少、或讲解仍然云里雾里？

4. Phase 4 试点定义是否足够清楚？
   - 图书线完整跑 `022_丰饶时代` 的交付物是否明确？
   - Skill 线完整跑 `gstack/browse` 的交付物是否明确？
   - 用户验收从“校准表格”切到“成品阅读体验”是否正确？
   - 成品页的失败条件应该是什么？

5. 我们下一步到底该做什么？
   - 是先修 Phase 2/3 骨架？
   - 是直接跑 `022_丰饶时代` 成品页？
   - 是先让 `gstack/browse` 复评通过？
   - 还是需要重新定义 Phase 4 的验收方式？

## 不要修

## Phase 4 验收闸门

## 已踩坑复发风险

- 解释性推理过多。
- 报菜名。

## 给执行者的下一步

给出 3-7 条下一步动作，按优先级排序。
