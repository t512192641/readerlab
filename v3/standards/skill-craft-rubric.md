# Skill 线可上手性评分标准

本标准评价 Skill / 工程材料的净化正文、技术负责人解读、复现配方和资产卡。目标是让没读过原材料的产品负责人或 Agent 接触可信的一手主体，理解关键机制，并准确知道哪些结论已经验证、哪些没有。

## 先锁定评价对象与状态

每次评分先写明对象、版本、材料边界、复现 profile、已读证据和本次验收链段。以下状态不能通过平均分互相升级：

- **通过**：只覆盖点名对象、profile 和实际验收链段。
- **局部通过**：只保护已通过的片段或链段；不得推成整页、整包、Skill 线或完整流水线通过。
- **待复评**：旧判定不作废，但在完成指定新证据前不得当作当前通过证据。
- **浅材料**：源材料不足以支持深机制、方法论或迁移结论；允许形成可追溯的主读页，不得靠 AI 或外部知识补成“深度解读”。
- **淘汰**：触发即死条件，或核心适用维度低于 3 分。

评分为 1—5：1 分废弃，2 分平庸，3 分可用，4 分有用，5 分强可复用。只评材料确实适用的维度；`不适用` 必须给出源证据，且不能抬高总评。来源真实性与页面职责分离始终适用。

## 维度一：一手主体可信

| 分数 | 判定 |
| --- | --- |
| 1 | AI 摘要、翻译式转述或文件介绍冒充正文。 |
| 2 | 看似保留原意，但可见单元无法逐一回到来源。 |
| 3 | 每个正文单元有源锚点，重要删除有理由。 |
| 4 | source map 能证明保留、移动、删除、合并和重排，正文约束强度未改变。 |
| 5 | 第三方能据 source map 复核正文与删除边界，且主读页仍自然可读。 |

高分信号：主读页保留源材料的用途、触发、判断顺序、流程、约束、失败和输出，路径、日志、执行外壳与 AI 解释各归其位。

## 维度二：机制走查完整

| 分数 | 判定 |
| --- | --- |
| 1 | 只说材料能做什么。 |
| 2 | 列出步骤，但输入、状态或退出条件缺失。 |
| 3 | 能从输入走到输出，但仍有关键黑箱。 |
| 4 | 讲清适用的状态、分支、权限、人工门、失败、恢复和停止。 |
| 5 | 读者能重建关键状态转换，并解释每个门如何改变系统行为。 |

高分信号：解读 `gstack/spec` 时讲清从 Why、边界、证据、草稿确认到质量与安全门，再到不同输出分支的状态变化，而不是把它概括成“写 issue 的 prompt”。

## 维度三：取舍与反事实讲透

| 分数 | 判定 |
| --- | --- |
| 1 | 只描述现状或赞美设计。 |
| 2 | 说“更安全 / 更完整”，但不说代价。 |
| 3 | 提到收益和代价，反事实仍模糊。 |
| 4 | 说明为什么这样设计、不这样做会坏在哪里。 |
| 5 | 同时讲清收益、成本、替代方案、失败后果和适用边界。 |

高分信号：说明“不许第一轮就写 issue”是在牺牲速度换可执行性，并指出跳过后执行者会在哪些决策上只能靠猜。

## 维度四：条件式判断有证据

| 分数 | 判定 |
| --- | --- |
| 1 | 用模型名、时代判断或外部知识制造深刻感。 |
| 2 | 结论可能合理，但没有机制或来源证据。 |
| 3 | 能区分源事实、外部事实和解读判断。 |
| 4 | 方法论做到“模式—证据—作用—限制”一致，外部材料确实改变理解。 |
| 5 | 只启动必要扩展，并能说明省略其他扩展为什么更准确。 |

方法论指认、2026 设计评审和外部知识不是固定栏目。只有源机制或登记证据成立，或用户明确要求时才启动取证；用户要求不能免除证据，浅材料也不得借这些栏目被包装成深材料。

## 维度五：验证、复现与迁移边界准确

| 分数 | 判定 |
| --- | --- |
| 1 | 愿景、配方和完成声明混在一起。 |
| 2 | 有步骤名，没有判断、失败或停止条件。 |
| 3 | 新 Agent 能开始执行，且知道未覆盖范围。 |
| 4 | profile 覆盖源证据要求的关键机制，并记录输入、分支、门、失败处理和输出。 |
| 5 | 独立复现者能重建目标机制，证据可核对，迁移前提和不可迁移部分都明确。 |

局部静态检查、迷你页、资产卡冷启动、完整复现和真实隔离运行是不同证据等级。任何结论都必须点名所依据的等级；一个等级通过不能自动证明更大的链段。

## 页面职责检查

- 主读页只提供最小来源身份、净化正文和技术负责人页入口。
- 技术负责人页沿机制主线解释状态与分支、权限与人工门、取舍反事实、失败恢复停止、验证和迁移边界。
- 两页出现相同段落结构、相同摘要或相同结论清单，视为职责没有分离。
- 资产卡是给 Agent 的独立复用对象，不得反向污染主读页，也不得依赖回读源文件补背景。

## 复现测试

复现前为样本建立 profile：列出不可缺少的行为、源证据、允许输入、停止条件和预期输出。把配方单独交给没读过原材料的新 Agent；按 profile 逐项记录覆盖、偏离和证据，不用固定百分比替代关键机制判断。

任何 profile 至少按适用性检查：

- 触发与不触发场景；
- 输入、关键状态、处理分支、输出和停止条件；
- 权限、外部输入、宿主差异与人工门；
- 失败、拒绝、恢复和接管者；
- 新 Agent 的第一步、验证方式与适用边界。

### `gstack/spec` 校准 profile（Phase 1 基线）

`gstack/spec` 只用于 Phase 1 校准与资产卡基线，不是 Phase 4 完整 Skill 试点。profile 保留：启动状态探测、Why 与边界的分阶段询问、读代码或材料证据后再问技术问题、草稿确认、质量审查、脱敏 / 安全、归档 / 发 issue / 派生执行分支、STOP 点，以及用户决策优先于模型共识。

### `gstack/browse` Phase 4 profile

Phase 4 完整 Skill 成品试点的 profile 保留：浏览器使用边界、持久状态、命令总账、本地服务入口、权限 token 分级、网页内容不可信、文件出口与真实路径安全、底层接口白名单、验证码 / 扫码 / 多因素登录的用户接管、截图与日志证据、健康检查与恢复，以及无法安全或可验证地继续时停止。

该 profile 不能凭迷你成品页、单张资产卡或局部测试通过；完整复现至少需要逐单元 source map、独立 Agent 复现结果和可核对机制证据。是否真实跑通完整链路，另由运行完整性门判定。

## 历史正反例回归

历史 case 的身份、证据路由和预期判定只引用 `v3/standards/regression-suite.md` 的 Skill 表，不在本 rubric 另建一套事实：

- `S-P01`、`S-P02` 只保护各自已证明片段，不能扩大通过范围。
- `S-N01`—`S-N08` 分别覆盖来源替代、工程外壳冒充主体、页面换皮、happy path、无证据标签、无关外部知识、资产卡无法冷启动和局部测试升级声明。
- 回归时按 case 指定证据读取；`待复评`、`浅材料`、`局部通过` 维持原作用域，除非新增对应证据并完成重新验收。

## 即死条件

触发条件与历史预期以 `regression-suite.md` 的 `S-N01`—`S-N08` 为准。新增成品还需立即淘汰以下情况：逐单元 source map 缺失或重要删除无记录；技术负责人页回避材料实际存在的失败 / 恢复 / 停止；未说明不可迁移部分；把未执行的冷启动、复现或真实运行写成已通过。
