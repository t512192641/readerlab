# Skill 线可上手性评分标准

本标准评价 Skill / 工程材料的逆向工程产物：主读页、技术负责人页、方法论指认、设计评审、复现配方和资产卡。目标不是夸这个 Skill，而是让没读过原 Skill 的人或 Agent 能理解、评审并复现关键机制。

评分：1 分废弃，2 分平庸，3 分可用，4 分有用，5 分强可复用。低于 3 分不得进入成稿。

## 维度一：机制走查完整

| 分数 | 判定 |
| --- | --- |
| 1 | 只说这个 Skill 能做什么。 |
| 2 | 列出步骤，但输入、状态和退出条件缺失。 |
| 3 | 能从触发走到输出，但有黑箱。 |
| 4 | 说明输入、处理、状态、分支、输出和停止点。 |
| 5 | 读者能画出状态机，并知道每个门为什么存在。 |

高分例：解读 `gstack/spec` 时说明它不是“写 issue 的 prompt”，而是一个五阶段漏斗：先锁定 Why，再锁边界，再读代码证据，再让用户确认草稿，再过质量和脱敏门，最后才归档、发 issue 或派生执行代理。

低分例：这个 Skill 会把模糊需求整理成 GitHub issue，并可以自动派给 Claude 执行。

## 维度二：取舍讲透

| 分数 | 判定 |
| --- | --- |
| 1 | 只描述现状。 |
| 2 | 说“更安全 / 更完整”，但不说代价。 |
| 3 | 提到取舍，缺少反事实。 |
| 4 | 说明为什么这样设计，不这样做会坏在哪里。 |
| 5 | 同时说清收益、成本、替代方案和适用边界。 |

高分例：`gstack/spec` 的硬门“不许第一轮就写 issue”是在牺牲速度换可执行性；如果跳过，agent 会把用户一句想法包装成貌似完整的 issue，后续执行者只能靠猜。

低分例：它要求多轮提问，所以需求会更清楚。

## 维度三：方法论指认准确

| 分数 | 判定 |
| --- | --- |
| 1 | 乱贴模型名。 |
| 2 | 模型名正确但没有对应机制。 |
| 3 | 能指出一个真实模式。 |
| 4 | 模式、证据和作用三者一致。 |
| 5 | 能把局部设计抽象成可迁移方法，同时保留限制。 |

高分例：把 `Phase 4.5a` 和 `4.5b` 指认为“双层内容安全门”：先用语义审查补正则盲区，再用确定性扫描兜底；这不是泛泛的“安全意识”，而是 scan-at-sink 的发布前护栏。

低分例：这里体现了第一性原理和闭环思维。

## 维度四：评审可信

| 分数 | 判定 |
| --- | --- |
| 1 | 只有好坏评价。 |
| 2 | 建议空泛，不可执行。 |
| 3 | 有具体建议，但没有风险排序。 |
| 4 | 建议能落到具体结构、协议或删减点。 |
| 5 | 像技术负责人在 2026 年重新审这个设计：知道该砍什么、保什么、替换什么。 |

高分例：评审 `gstack/spec` 可指出：AskUserQuestion 兼容层和 telemetry 段落在阅读上噪声很大，但在原 Skill 中承担跨宿主兼容和自改进目的；ReaderLab 主读页应剥离，技术负责人页要保留其设计理由和失败模式。

低分例：建议减少一些复杂流程，让 Skill 更简洁。

## 维度五：配方可执行

| 分数 | 判定 |
| --- | --- |
| 1 | 只有愿景。 |
| 2 | 有步骤名，没有判断条件。 |
| 3 | 可以照着写 happy path。 |
| 4 | 包含输入、阶段、门禁、失败处理和输出格式。 |
| 5 | 新 agent 不读原 Skill，仅凭配方即可写出覆盖原 Skill 70% 以上关键机制的骨架。 |

高分例：复现配方要求先定义触发词和禁止事项，再写启动状态探测，再写五阶段询问与草稿确认，再加质量门、脱敏门、归档 / issue / spawn 三条分支，并规定每个 STOP 点的行为。

低分例：先了解用户需求，再整理成 issue，最后让用户确认。

## 复现测试

把复现配方单独交给一个没读过原 Skill 的新 agent。它必须产出一个 Skill 骨架，覆盖原 Skill 至少 70% 的关键机制。

关键机制清单至少包括：

- 触发条件和不该触发的场景。
- 启动状态探测。
- 分阶段询问，不跳过 Why 和边界。
- 读代码或材料证据后再问技术问题。
- 草稿确认门。
- 质量审查门。
- 脱敏 / 安全门。
- 归档、发 issue、派生执行三种输出分支。
- STOP 点和失败处理。
- 用户决策优先于模型共识。

## 即死清单

- 只把原 Skill 翻译成中文。
- 把命令行噪声当主体。
- 用“闭环、第一性原理、系统思维”等词替代机制解释。
- 技术负责人页和主读页写成两份换皮摘要。
- 资产卡离开原文就看不懂。
- 评审建议无法执行。
- 复现配方缺少判断条件。
- 忽略失败、权限、宿主差异和人工门。
- 把个人偏好当成可复用方法。
- 未说明哪些内容不值得继承。
