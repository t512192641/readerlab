# V3 继承资产

本文只记录 V3 继续继承的旧线判断。V3 抛弃旧线的 runner、validator、demo builder、quality gate adapter 和生成用 Python，但不抛弃已经被验证正确的产品判断。

## 继续继承

1. 正文优先：图书和长文保留原样或轻清理正文；Skill 和工程材料生成净化正文。AI 只能降低理解成本，不能冒充一手材料。来源：`docs/decisions.md` D-002。
2. 读者页和事实层分离：读者看到自然中文阅读页；source registry、location map、contracts、trace、eval 等事实进入 audit 或 V3 等价事实区。来源：D-003。
3. 正文和陪读同页：每个阅读单元默认是一页可批注 Markdown，正文附近只放有价值陪读，不恢复三分文件结构。来源：D-007。
4. 专家价值裁决：陪读必须解决具体阅读问题、机制、边界、误读、反例或迁移判断；通用总结不能冒充陪读。来源：D-009。
5. 机器通过不等于读者验收：结构检查只能证明底线，不能声明阅读质量通过。V3 改用标准、样张和用户判定校准裁判。来源：D-005、D-010。
6. 图书路线保留候选和选择链：先产出候选，再说明选用、合并、降级和放弃原因，读者页只装配已选内容。来源：D-023。
7. Skill 双视角：主读页负责净化正文和低门槛理解；技术负责人页解释工程结构、设计取舍、失败保护、复用边界和代价。来源：D-027。
8. Skill 资产卡冷启动：资产卡必须能离开原始 source 独立说明问题、做法、边界和第一步。V3 沿用 `purpose`、`reader`、`use_boundary`、`selection_rule` 四字段。来源：D-031。
9. 中文交付面：读者可见目录、文件名、页面标题和栏目名默认中文。来源：D-033。
10. 陪读质量优先于数量：删除低价值干扰，但保留真正带来机制、经济、历史、政治、组织、工程、心理等增量的批注。来源：D-034。
11. 生产约束和验收约束分层：生成前只固定来源、正文、结构、边界等硬事实；内容好坏交给 rubric、裁判和用户校准。来源：D-035。
12. gstack 源仓库只读：它是学习材料，不删除、不移动、不改写。来源：D-021。

## 降级继承

`experiments/readerlab-v2/cognitive-lens-checklist.md` 的价值是盲区审计，不再是生成器。V3 可以在裁判阶段检查是否遗漏 grounding、结构、机制链、隐含假设、适用边界、迁移启发和候选沉淀，但不得把透镜清单机械铺进读者页。

## 明确抛弃

- 抛弃用 Python 生成 ReaderLab V3 内容。
- 抛弃字符串式 validator 作为质量通过依据。
- 抛弃把 demo 内容硬编码进脚本。
- 抛弃用模型名、术语名、流程名替代解释。
- 抛弃没有用户金标校准就继续扩写协议。
