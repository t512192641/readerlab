# 会话 3：ABC 路线——桥梁生成近终稿陪读

## 输入

你只能读取：

- `pilot-inputs/U01.md`
- `pilot-inputs/U02.md`
- `pilot-inputs/U03.md`
- 本任务文件
- `05_PRODUCT_RULES.md`
- `06_OUTPUT_FORMAT.md`

不得读取 ReaderLab 仓库其他文件、历史结果、D 路线结果或答案说明。

## 目标

对每个完整主题单元，通过 A → B → C 找到可能被直接路线忽略的外部认知，并写出最多 1 条近终稿陪读。

允许沉默。

## 每个单元的固定步骤

### 1. A：读取完整原文

从原文中提取最多 4 个值得重新观察的具体关系 A。

### 2. B：生成关系桥梁

为每个 A 生成最多 2 个 `B-core`。

`B-core` 必须：

- 去掉原文学科词后仍然清楚；
- 包含具体关系或机制；
- 不能是万能句；
- 不能只是原文摘要；
- 不得写人物、理论或书名。

可能但未经 A 支持的延伸单独标为 `B-hypothesis`，不得混入 `B-core`。

### 3. 选择最多 2 个 B 进入搜索

优先选择：

- 忠实；
- 非复述；
- 能打开不同知识传统；
- 认知回报可能高于理解成本。

### 4. C：真实外部搜索

每个入选 B：

- 前 3 个查询不得使用原文直接领域词；
- 至少翻译为 2 个不同领域的问题表达；
- 沿作者、书籍、论文或思想谱系核验；
- 不得为跨域而硬凑。

### 5. 最多保留 4 个 C 候选

按 `05_PRODUCT_RULES.md` 淘汰反例。

### 6. 只选择最好的 1 个

若没有候选通过，输出 `SILENCE`。

### 7. 恢复 C 的真实深度

只展示来源支持的 M1/M2/M3。不得把 ReaderLab 整理的步骤冒充原作者方法。

### 8. 写近终稿陪读

严格使用 `06_OUTPUT_FORMAT.md`。

## 搜索预算

每个单元与 D 路线相同：

- 最多 10 个查询；
- 最多打开 15 个页面；
- 至少核验 2 个不同来源。

## 输出

```text
abc-output/
├── U01.md
├── U02.md
├── U03.md
├── bridge-and-candidate-ledger.md
└── runner-manifest.md
```

完成后停止，不得查看或评价 D 路线。
