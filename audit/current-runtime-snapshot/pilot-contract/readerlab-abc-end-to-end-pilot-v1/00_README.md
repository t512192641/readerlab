# ReaderLab：ABC 最小端到端成品对照实验 v1

## 本轮只回答一个问题

> 在完整主题单元上，ABC 路线最终写出的陪读，是否比“直接从原文寻找外部知识”的路线更值得保留？

不再单独测试 A、B、C 的内部零件，也不建设混合触发器、知识库、M1/M2/M3 系统或生产流水线。

## 两条路线

### D 路线：直接路线

完整阅读主题单元，直接搜索真实外部认知对象 C，选择最好的一条，写成近终稿陪读。

### ABC 路线：桥梁路线

完整阅读主题单元，先提炼多个 B，再用 B 进行结构性跨域搜索，选择最好的一条 C，写成同等长度、同等完成度的近终稿陪读。

## 公平性要求

两条路线必须：

- 使用同一模型；
- 使用同一思考强度；
- 使用同一种搜索工具；
- 使用相同的查询和页面预算；
- 使用完全相同的成品格式；
- 彼此隔离，不得读取对方结果；
- 不得读取历史接受稿、历史 C、答案说明或产品判词。

## 测试材料

优先使用历史证据包中的冻结输入：

- F01：历史上曾产生产品接受陪读的材料；
- F02：容易滑向结构化复述的材料；
- F04：较难、但历史上曾出现值得写方向的材料。

只复制冻结原文输入。不得复制答案说明、历史 Reader、候选或来源审核。

如果仓库中无法定位 F01/F02/F04，停止并报告缺失，不得自行替换材料。

## 会话安排

共需要 4 个新会话：

1. 输入封装会话：只准备并冻结 3 份原文。
2. D 路线生成会话：处理全部 3 份原文。
3. ABC 路线生成会话：处理全部 3 份原文。
4. 独立装配与审核会话：技术审核、匿名配对，不替产品负责人做最终选择。

## 最终产品判断

产品负责人只看 3 组匿名成品对照，每组选择：

- 左边更好；
- 右边更好；
- 都值得；
- 都不值得；
- 难以判断。

完成盲审后才揭示路线。

## 本轮成功标准

### ABC 进入下一版 ReaderLab 的第二发现通道

满足任一条件：

- ABC 在 3 组中至少赢 1 组，并且另外至少 1 组不劣于直接路线；
- 或 ABC 贡献了一条直接路线没有找到、产品负责人明确愿意保留的陌生高价值陪读。

### 暂不工程化 ABC

出现以下情况：

- ABC 0 组胜出；
- ABC 的主要结果是牵强跨域、专业扩展或理论贴名；
- ABC 的额外成本明显更高，但成品没有产品增量。

本轮不决定完整 ReaderLab 架构。
