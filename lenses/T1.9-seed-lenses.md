# T1.9 种子透镜 v1

## 1. 定位与使用边界

本文件只包含五个阶段性种子透镜。它们从
`blueprints/EXECUTION-ROADMAP.md` 列出的候选起点——激励、演化选择、系统反馈、
生产力史观、博弈论——以及本任务获准读取的三个正例逆向编译而来。候选起点不是
封闭或永久透镜清单；真实材料中的缺口仍可由临时专家按
`contracts/T1.4-expert-and-knowledge-card.md` 探索。

透镜是可检查的问题程序，不是现成答案、预制洞见或主题摘要。每次使用必须先由
原文证据满足“适用触发器”，再按顺序回答“强制提问序列”；不得因为透镜名称听起来
相关就套用。证据不足时，合法输出是 `unknown` 或“不使用本透镜”，不能补写材料
没有提供的事实。

透镜只提出候选承重主张及其边界；每条候选以一句话表达，候选条数由当次获授权的
任务或运行另行冻结，本文件不设数量。候选供 T1.4 的四类伪增量探针、删除测试和
去重预筛继续处理。透镜不直接生成 Writer 成品，不锁定知识卡，也不替代独立审核、
T2.2 资格考试、裁判 gate 或产品负责人判词。

下列每个 `lens id` 与 `version` 只是本批种子的可追溯身份，不冻结序列化 schema 或
调用接口。若未来实际调用为正式透镜，producer lineage 仍须按 T1.4 明确绑定
`formal-lens / lens id / version`。

## 2. 共用执行规则

1. 只处理当前原文锚点及获准上下文，不把正例中的结论移植成新材料的答案。
2. 每个问题都要给出原文依据、明确写为假设，或回答 `unknown`；不得把透镜常识当成
   材料事实。
3. 一次候选只承载一个主要判断能力。若多个透镜得到功能相同的主张，按 T1.4 去重，
   不用不同学科标签扩充数量。
4. 输出仍须接受原文直述、后文透支、明显推论、术语换名、删除测试与证据边界检查；
   透镜命中不等于候选幸存。
5. 每个透镜的“输出类型限定”只限制输出的完整性和可核对性，不限制合法增量类别。
   机制、模型、方法、预测、权衡、可迁移关系、高手指点、跨行业视角八类始终整体
   开放；实际归类由材料支持的承重主张决定。

## 3. 种子透镜

### L1 激励：承诺改变行为后的责任检验

- `lens id`：`seed-incentive-responsibility`
- `version`：`v1`

#### 适用触发器

当原文出现服务承诺、能力转交、任务委托或备用安排，而且该安排可能改变参与者的
注意力、练习、准备或风险承担时，使用本透镜。若材料没有可定位的承诺、行为主体或
异常情境，不得仅凭“人会偷懒”之类的常识触发。

#### 强制提问序列

1. 原文在当前锚点究竟承诺了什么，承诺前后谁负责哪项行动？
2. 如果参与者相信并正常使用这项承诺，他们有哪些行为会合理改变？
3. 这些行为变化会让哪些注意力、信息、熟练度、资源或待命能力减少？材料能支持到
   哪一步，哪一步仍是 `unknown`？
4. 在什么异常、边界或失败时刻，原有安排会试图把行动责任交回给谁？
5. 被交回责任的一方，是否正因第 2—3 问的行为变化而难以及时、可靠地行动？
6. 为避免这种自我矛盾，承诺方至少需要承担到哪个责任边界？哪些具体实现仍未决定？
7. 哪些条件会让上述链条不成立，例如持续练习、充分预警、能力未转移或另有可靠
   备用者？

#### 输出类型限定

只允许输出零条或任意数量的候选（包括一条），不预设条数：

- 零条时输出 `unknown`／不形成候选，并指出缺少的是承诺、行为变化、异常回交还是
  边界证据；
- 有候选时，每条都必须以一句话表达，完整连接“原文承诺—激励下的行为变化—
  可用能力变化—责任边界”，并显式附上成立条件与未冻结细节，再进入 T1.4 预筛。

候选可落入八类合法增量中的任一类，但不得直接写成安全规范、责任归属判决、产品
要求或已经锁定的知识卡。

#### 懒惰应用反例

看见“可以把任务交给系统”，就直接写“所以系统必须绝对安全”；中间既不检查承诺
怎样改变人的注意力或练习，也不验证异常时责任是否真的回流，还凭空定义何为
“安全状态”。这只是立场口号，不是激励问题程序的结果。

#### 来源

- 路线候选来源：`blueprints/EXECUTION-ROADMAP.md`“专家、透镜与持续改进”列出的
  阶段性候选起点“激励”。
- 正例逆向来源：`examples/book/positive/automatic-driving-safe-state.md`。实际使用
  的是“先检查承诺如何改变乘员状态，再追问异常责任边界”的结构动作；不移植该
  样张对自动驾驶的具体结论。

### L2 演化选择：什么被筛选、保留与丢失

- `lens id`：`seed-evolution-selection`
- `version`：`v1`

#### 适用触发器

当原文讨论群体、制度、技术、观念或实践的延续、扩张、适应、衰退、消失或代际变化，
并隐含“为什么这一种留下、另一种没有”时，使用本透镜。只有兴衰叙事、却没有可辨认
的变化单位、传递过程或选择环境时，先回答 `unknown`，不得强贴演化标签。

#### 强制提问序列

1. 被观察的变化单位是什么：群体、制度、技术、观念、实践，还是其他对象？
2. 同一单位存在哪些可区分的变体；这些变体通过什么过程被复制、学习、继承或保留？
3. 哪些环境约束或竞争条件造成差异性保留，而不是仅仅同时发生？
4. 哪些特征提高了当前环境中的延续机会；它们是否同时制造了长期脆弱性或维护成本？
5. 材料是否只展示幸存者或失败者？缺失的对照、未被记录者和替代解释是什么？
6. 选择发生在哪个时间尺度和层级；一个层级的“适应”会不会损害另一个层级？
7. 环境、传递机制或观察窗口怎样变化时，当前解释会失效？

#### 输出类型限定

只允许输出零条或任意数量的候选（包括一条），不预设条数。零条时说明缺失证据并
输出 `unknown`／不形成候选；有候选时，每条都必须以一句话明确写出“变化单位—
变体—选择环境—
传递或保留结果—时间与失效边界”。候选可以属于任一合法增量类型，但不得把“存活”
写成“更优”，不得把结果倒写成目的，也不得从一个案例推出普遍的文明、社会或技术
定律。

#### 懒惰应用反例

看到某种制度延续或一个文明衰亡，就写“适者生存”。没有说明谁在变、什么能传递、
环境筛掉了什么，也把幸存当成优秀、把消失当成必然。这只是用演化词汇重命名结果。

#### 来源

- 路线候选来源：`blueprints/EXECUTION-ROADMAP.md`“专家、透镜与持续改进”列出的
  阶段性候选起点“演化选择”。
- 正例逆向来源：`examples/book/positive/civilization-lifecycle.md`。实际使用的是
  “把文明会消失的原文前提展开为可追问的延续、耗散与知识丢失过程”；不把样张中的
  人物、书目、代际说法或崩溃解释预置为其他材料的答案。

### L3 系统反馈：结果怎样返回并改变下一轮条件

- `lens id`：`seed-system-feedback`
- `version`：`v1`

#### 适用触发器

当原文描述一个行动反复发生、某种存量持续积累或消耗，或者当前结果会回过头改变
下一轮行动条件时，使用本透镜。若材料只给出一次性因果或并列现象，不能因为出现
“系统”“循环”等词就触发。

#### 强制提问序列

1. 系统边界内有哪些会随时间变化的关键量；哪些是存量，哪些是改变存量的过程？
2. 原文中的初始行动先改变了哪个量，方向是什么？
3. 该变化通过哪条可说明的路径返回，影响下一轮行动、能力或约束？
4. 返回作用会放大原变化、抵消原变化，还是在不同阶段改变方向？
5. 路径中有哪些延迟、维护成本、容量上限、同步效应或观察不到的中间环节？
6. 哪个外部输入或替代原因也能解释同一结果；现有材料能否区分？
7. 在什么边界、时间尺度或参数变化下，反馈链会减弱、断裂或反转？

#### 输出类型限定

只允许输出零条或任意数量的候选（包括一条），不预设条数。零条时说明缺失证据并
输出 `unknown`／不形成候选；有候选时，每条都必须以一句话逐段核对“关键量—
变化方向—返回路径—
延迟或约束—失效边界”。证据只支持相关性时必须写成待检验假设，不得升级为已证实
因果。输出可以归入八类任一合法增量，不要求固定画图格式或字段 schema。

#### 懒惰应用反例

把“问题越来越严重”改叫“恶性循环”，却不指出哪个量增加、结果从哪里返回、经过
多久生效，也没有边界或替代原因。换成系统术语并没有增加读者的判断能力。

#### 来源

- 路线候选来源：`blueprints/EXECUTION-ROADMAP.md`“专家、透镜与持续改进”列出的
  阶段性候选起点“系统反馈”。
- 正例逆向来源：`examples/book/positive/civilization-lifecycle.md` 与
  `examples/book/positive/demand-pooling.md`。实际使用前者把维护成本、群体状态与
  衰退组织成过程的结构动作，以及后者对聚合稳定性和同步需求失效边界的追问方式；
  不把任一具体机制当成新材料的默认解释。

### L4 生产力史观：能力变化如何重组配置与关系

- `lens id`：`seed-productive-capacity-history`
- `version`：`v1`

#### 适用触发器

当原文把技术、基础设施、组织方式或协调能力的变化，与生产、分配、所有权、劳动、
备用容量或社会关系的变化联系起来时，使用本透镜。若只有“新技术更先进”的评价，
没有可比较的旧安排与新安排，不得触发。

#### 强制提问序列

1. 变化前，谁以什么单位拥有、生产、分配或预留哪种能力？
2. 哪项技术或组织能力改变了可行边界；它具体减少了什么约束或增加了什么协调能力？
3. 变化后，生产或配置单位怎样重组，哪些原本分散的能力被集中、共享或重新分工？
4. 所谓生产力收益来自更多产出、更少闲置、更少备用、更快周转，还是把成本转移给
   了别处？材料支持哪一种？
5. 谁获得收益，谁承担劳动、维护、风险、等待或失去控制的代价？
6. 当时有哪些资源、规模、制度或需求条件让这次重组可行；是否存在同样可解释结果的
   非技术路径？
7. 哪些同步需求、稀缺瓶颈、维护负担或分配冲突会缩小甚至逆转收益？

#### 输出类型限定

只允许输出零条或任意数量的候选（包括一条），不预设条数。零条时说明缺失证据并
输出 `unknown`／不形成候选；有候选时，每条都必须以一句话核对“旧配置—能力变化—
新配置—
收益与代价—历史条件和失效边界”。候选可属于八类任一合法增量，但不得把技术变化
写成单线决定论，不得用“效率提升”代替容量核算，也不得从局部重组推出整段历史
必然如此。

#### 懒惰应用反例

看到软件提高资产使用率，就写“生产力进步必然改变社会”。既没有说明过去为什么要
各自预留能力，也不区分减少闲置和转移成本，更不检查同步需求与分配代价。这只是
宏大结论，不是对生产能力重组的检查。

#### 来源

- 路线候选来源：`blueprints/EXECUTION-ROADMAP.md`“专家、透镜与持续改进”列出的
  阶段性候选起点“生产力史观”。
- 正例逆向来源：`examples/book/positive/demand-pooling.md`。实际使用的是“比较
  分散配置与共享配置，解释收益来自何处，并检查同步需求边界”的结构动作；不预置
  需求池化概念或共享车队结论。

### L5 博弈论：相互预期下的稳定选择检验

- `lens id`：`seed-strategic-interdependence`
- `version`：`v1`

#### 适用触发器

当至少两个行动方的结果彼此依赖，各方会依据他人的承诺、选择、信息或预期调整自身
行动时，使用本透镜。单人决策、纯机械因果或材料未给出行动空间时，不得把任何冲突
都叫作博弈。

#### 强制提问序列

1. 行动方分别是谁；同一个组织内部的角色是否真的拥有不同选择与责任？
2. 每一方在什么时点知道什么、能做什么；行动是同时、先后还是以承诺先行？
3. 各方实际关心的收益、成本、风险和约束有哪些原文依据，哪些仍是 `unknown`？
4. 在对方保持当前选择时，每一方改变自己的行动会得到什么后果？
5. 当前安排依赖哪些承诺、监督、惩罚、声誉、共享规则或可信备用机制才能稳定？
6. 个体上稳定的选择是否与整体更好的结果不同；差额由谁承担？
7. 改变信息、顺序、责任或资源规则后，各方的选择与结果可能怎样改变？
8. 哪些未建模行动方、外部性或非策略性机制会推翻当前解释？

#### 输出类型限定

只允许输出零条或任意数量的候选（包括一条），不预设条数。零条时说明缺失证据并
输出 `unknown`／不形成候选；有候选时，每条都必须以一句话明确包含“行动方—
可选行动—相互依赖—
稳定所需条件—边界”。候选可以是八类任一合法增量；不得凭直觉虚构收益值，不得把
动机猜测当事实，不得把稳定结果等同于最好结果，也不得直接给出制度处方。

#### 懒惰应用反例

写“只要大家理性就会合作”，却不列行动方、行动顺序、各自代价和让承诺可信的条件；
或者把共享资源一概叫“零和博弈”。这既不能预测选择，也不能解释安排为何稳定。

#### 来源

- 路线候选来源：`blueprints/EXECUTION-ROADMAP.md`“专家、透镜与持续改进”列出的
  阶段性候选起点“博弈论”。
- 正例逆向来源：`examples/book/positive/automatic-driving-safe-state.md` 与
  `examples/book/positive/demand-pooling.md`。实际使用前者对承诺、乘员行为和异常
  责任相互依赖的检查，以及后者对个人备用选择与共享配置成立条件的检查；不把
  自动驾驶或共享车队的具体答案迁移到其他材料。

## 4. 八类增量保持开放

本批五个透镜只是阶段性问题入口，不是能力边界。任何透镜在材料支持时，都可以提出
机制、模型、方法、预测、权衡、可迁移关系、高手指点或跨行业视角候选；任何一种
候选也都可能被 T1.4 预筛或后续独立审核淘汰。透镜未命中不等于材料没有价值，透镜
库没有覆盖的真实问题可以转交临时专家探索。

因此，本文件不得被解释为：

- 合格增量必须来自这五种框架；
- 每个锚点必须调用一个或多个透镜；
- 一个透镜必须产出固定数量、长度或类别的候选；
- 透镜命中、预筛幸存或生成成功等于独立审核通过、语义合格或产品接受。

## 5. 版本与治理边界

- 本文件是 `draft`。只有 M1 按路线图完成语义不变的独立冻结与 hash receipt 后，
  对应版本才可称为 `frozen`；本文件不自称已经冻结、通过资格或获得产品接受。
- 任一透镜版本一旦被调用或引用，不得原位覆盖。语义调整必须建立新版本，保留旧版
  及其使用结果、合格／质疑／失败和原因。
- 系统只能提出升降、调整或退役建议，不得自动执行晋升、降级、覆盖、删除或退役；
  治理动作由未来获授权的人工复盘决定。
- 本文件不冻结治理阈值、模型、Prompt、调用 schema、候选数量、调用粒度、治理周期、
  晋升规则、执行者、界面或 `tandem-comments` 接口。
- 正例读取权只属于本次透镜开发。生产运行不得沿本文件的来源引用读取
  `GOLD-STANDARDS.md` 或 `examples/`，也不得把本批种子当作生产能力证明。
