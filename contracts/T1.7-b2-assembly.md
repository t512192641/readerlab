# T1.7 B2 组装合同

## 1. 目的与责任

B2 把已经锁定并由 Writer 定稿的陪读，作为 Obsidian callout 就近插入它所回应的原文。它只在值得深入处出现，并为读者提供真实认知增量；不能只是复述、整理、换名或笼统提醒。

本节点只负责组装与追溯，不重新判断选题、价值、事实、重复或边界。内容是否获准进入 Writer 由上游锁定结果决定；本节点不能捞回任何未获准内容。

## 2. 输入前提

每个待组装项必须同时具备：

1. 当前材料与当前冻结范围内的对应原文，以及足以完成可见就近插入的位置关系；
2. 一份已锁定知识卡所对应的 Writer 定稿标题与正文；
3. 稳定、非空的 `knowledge-card-id`；
4. 完整、非空且原样传递的 `producer kind/id/version`；
5. 能证明该 Writer 定稿来自上述同一知识卡与 producer lineage 的绑定关系。

本合同不依赖 T1.2 或 T1.6 的既有合同文件。执行时只消费责任边界处已经交付的原文视图、Writer 定稿与 lineage；缺少任一前提时硬阻塞，不得猜测、补造或自行改写。

## 3. 输出单元

一个 Writer 定稿对应一个独立 B2 单元。单元按下列顺序输出，字段名和 callout 首行不得改写：

```markdown
<!-- readerlab-b2
b2-item-id: <稳定且非空的不透明标识>
knowledge-card-id: <上游稳定 knowledge-card-id>
producer:
  kind: <上游 producer kind>
  id: <上游 producer id>
  version: <上游 producer version>
product-value-label: unknown
-->
> [!note] AI 陪读｜标题
> Writer 定稿正文
```

`> [!note] AI 陪读｜标题` 是 Obsidian callout 的精确执行格式；其中“标题”替换为 Writer 定稿标题。Writer 正文的每一段、空行和续行仅增加 callout 所需的 `> ` 结构前缀，去除该前缀后必须与 Writer 定稿逐字一致。

元数据注释与紧随其后的 callout 构成同一个不可拆分的 B2 单元。`b2-item-id`、`knowledge-card-id` 和 `producer kind/id/version` 必须在同一单元内直接绑定；不得依赖文件名、标题、排列位置或相邻单元推断 lineage。

## 4. `b2-item-id` 稳定性

- 每个逻辑 B2 项在首次组装前取得一个 `b2-item-id`。
- `b2-item-id` 是逻辑项的稳定标识；同一逻辑项跨多个冻结 B2 产物版本时可以保持同一 `b2-item-id`，但它不能替代冻结产物的版本或身份。
- 标题、正文或可见位置发生变化时，必须形成新的冻结 B2 产物版本与身份；旧冻结产物不得原位改写。
- 新冻结版本创建时，`product-value-label` 必须为 `unknown`。旧产品判词只对它所绑定的旧冻结版本与固定 scope 有效，不得自动继承到新版本。
- 不同逻辑项不得共用标识；已使用的标识不得转给另一项。
- 标识的具体编码方案尚未冻结，为 `unknown`；不得把可变标题、正文或未冻结的精确锚点直接当作标识。

若无法判断是同一逻辑项还是新项，停止该项组装并交主控技术门，不得自行合并或拆分身份。

## 5. 就近插入

callout 必须紧随它所回应的原文段落或原文块出现，并位于下一段无关原文之前。组装器不得把陪读集中到章末、文末、独立附录或与对应原文分离的汇总区。

同一原文位置若有多个已获准的 Writer 定稿，每个定稿仍使用独立 B2 单元，并保持输入已经冻结的次序；输入未给出可判定次序时硬阻塞，不得由组装器按偏好重排。

可见的 Markdown 就近关系不等于 `tandem-comments` 的交互锚点。`tandem-comments` 精确锚点格式保持 `unknown`；获得真实使用样例并由后续授权任务冻结前，不得猜测字段、编码、定位粒度或回复接口。

## 6. 产品价值标签位

每个生产 B2 单元都预留 `product-value-label` 标签位，其初始值和冻结后的值必须始终为 `unknown`。该标签位只声明未来产品判断维度，不是产品判词的写入位置；任何角色都不得靠原位修改被冻结生产产物写入判词。

未来真实产品判词允许使用的四个值仅为：

- `惊艳`
- `有用`
- `平庸`
- `废弃`

只有产品负责人可以给出四级标签；模型、组装器、独立审核者和主控技术门都不得代写、预测或把技术检查结果转换成产品判词。

未来真实产品判词必须写入独立、不可变的验收／判词记录，不得写回或覆盖冻结生产 B2 单元。每条记录至少同时绑定：

1. 对应的 `b2-item-id`；
2. 被评价的冻结 B2 产物的可信身份及内容哈希；
3. 判词适用的固定 scope／范围；
4. 产品负责人给出的四级标签。

验收／判词记录的具体文件路径和 schema 尚未冻结，为 `unknown`，只能由后续获授权任务决定。

产品判词只对上述绑定的冻结产物版本与 scope 有效。标题、正文或可见位置变化形成新冻结版本后，生产标签位仍为 `unknown`，必须重新取得产品负责人的判词；禁止从旧版本自动继承。`unknown` 不表示平庸、废弃、未实现或产品通过。

## 7. 无配额原则

B2 的数量和长度完全由价值与复杂度决定，不设数量与长度配额，也不设最少条数、最多条数、目标密度或统一篇幅。

- 不得为了达到数量而创建陪读、拆分一条内容或保留低价值内容。
- 不得为了缩短篇幅而删除承重解释，也不得为了显得深入而扩写。
- 当前范围没有获准的 Writer 定稿时可以为零；零条只是一项执行事实，不自动构成语义合格或产品接受。

## 8. 不可越过的职责边界

组装器必须逐字保留原文与 Writer 定稿，只能增加本合同规定的元数据、callout 结构前缀和物理插入位置。它不得：

- 重写、润色、摘要、截断、合并或扩写 Writer 标题与正文；
- 重新审核价值、事实、重复、边界或认知增量；
- 新增事实、承重主张、例子、推论、来源或措辞；
- 捞回淘汰、退回、待补证据或其他未锁定内容；
- 生成、修复、概括或替换 B1 原文；
- 把 B2 组装视图冒充 B1 交付、B1 正确性证据或原文 owner；
- 以 B2 替代 B1，或用 B2 的存在证明内容已获产品接受。

B2 组装视图可以为了就近阅读而呈现上游原文的逐字投影，但该投影不改变 B1 的独立身份与责任。

## 9. 硬阻塞与升级

出现下列任一情况时，停止受影响项或本次组装，不得降级继续：

- 对应原文或可见位置关系缺失、歧义或越出当前冻结范围；
- Writer 定稿、锁定资格或 lineage 缺失、冲突、空值或无法一一绑定；
- `b2-item-id` 重复、漂移、复用或身份边界无法判断；
- 只有改写 Writer 内容、添加事实或重新审核才能继续；
- 有人要求原位修改冻结生产 B2 单元写入产品判词，或要求非产品负责人给出四级标签；
- 有人要求生产 B2 组装读取验收／判词记录，或据此改变生产内容；
- 产品判词记录没有绑定 `b2-item-id`、冻结产物可信身份及内容哈希、固定 scope／范围和产品负责人标签；
- 标题、正文或可见位置变化后没有形成新冻结产物版本，或试图自动继承旧版本判词；
- 有人要求本合同猜测或冻结验收／判词记录的具体文件路径或 schema；
- 有人要求猜测或冻结 `tandem-comments` 精确锚点；
- 材料授权、产品事实、产品判断或 owner 决议存在缺口或冲突。

纯技术缺口交主控技术门处理，并把缺口、受影响对象与 `unknown` 状态向产品负责人清楚可见。产品判断、材料授权、产品事实和产品决议冲突只能由产品负责人决定；主控技术门不得代替。

## 10. 确定性检查

确定性检查由获准读取相应对象的环节分别执行；生产 B2 组装不得为了执行本节而读取验收／判词记录。每次生产组装至少检查适用的生产项，后续获授权的验收或主控核验再检查判词记录项：

1. 每个 callout 首行精确匹配 `> [!note] AI 陪读｜标题` 的结构；
2. 每个 B2 单元具有唯一且稳定的 `b2-item-id`；
3. 每个单元直接绑定一个 `knowledge-card-id` 与完整 `producer kind/id/version`；
4. callout 就近插入对应原文，且未集中搬运到远离原文的位置；
5. 去除 callout 结构前缀后的标题与正文和 Writer 定稿逐字一致；
6. 生产 B2 单元的 `product-value-label` 初始且保持 `unknown`，冻结生产产物没有被原位修改以写入判词；
7. 在后续获授权的验收或主控核验中，若存在产品判词记录，它独立且不可变，并绑定 `b2-item-id`、冻结产物可信身份及内容哈希、固定 scope／范围和产品负责人给出的四级标签；合同没有冻结其具体文件路径或 schema；
8. 标题、正文或可见位置变化时形成新冻结产物版本，新版本标签状态为 `unknown`，旧版本判词没有自动继承；
9. `tandem-comments` 精确锚点保持 `unknown`，输出没有创建任何锚点字段；
10. 没有数量或长度配额，没有重审、添事实、捞回内容或冒充 B1。

这些检查只能形成确定性 execution 证据，不能替代内容语义判断或产品负责人判词。
