# T1.5 知识卡独立审核合同

## 1. 责任与位置

独立审核位于知识卡生产之后、Writer 之前，负责逐张检查知识卡的价值、事实、重复与边界，并为每张卡形成一个可操作的审核终局。

本节点属于生产链中的内容入口门：

- 只有终局为**锁定**的知识卡可以进入 Writer。
- Writer 只能统一锁定卡的表达，不能参与本节点的选取、审核或终局变更。
- 独立审核不是产物冻结后的最终验收；锁定只表示获准进入 Writer，不表示已通过最终语义验收或获得产品负责人接受。
- 审核责任必须与知识卡生产责任、Writer 表达责任分开；本合同不规定由多少人、多少 Agent 或哪种实现承担该责任。

本合同自行定义审核所需的最小输入与输出边界，不要求、读取或依赖 T1.4 合同已经生成。上游实际产物只要满足本合同的输入条件即可受审；不满足时按本合同的阻塞规则处理，不得靠猜测补齐。

## 2. 审核输入边界

一次审核只处理当前已声明运行范围内的知识卡及其获授权证据。审核不得读取其他运行的产物、金标、反例判词、裁判答案或最终验收答案。

每张待审知识卡必须可识别并提供：

- 稳定的 `knowledge-card-id`；
- 原始的 `producer kind`、`producer id`、`producer version`，合称 `producer kind/id/version` lineage；
- 承重主张、来源锚点、证据状态与失效边界等足以完成四维审核的内容或可追溯引用。

待审卡来自当前运行的 `runs/<run-id>/raw/knowledge-cards.md`。审核者把它视为只读输入，不得在审核过程中直接改写卡片来使其通过。

以下情况在内容审核开始前构成技术阻塞：

- `knowledge-card-id` 缺失、为空或在当前待审集合中重复；
- `producer kind/id/version` 任一值缺失；
- 卡片或其引用无法在当前获授权范围内定位；
- raw 输入与 locked 输出无法保持独立路径。

材料是否获授权不由技术侧代判；授权缺失时必须停止并交由产品负责人决定。

## 3. 四个审核维度

每张卡的审核结果必须分别记录四个维度的具体结论、理由和所依据的卡内内容或证据位置。不得只给总评，也不得用一个维度的表现代替另一个维度的检查。

### 3.1 价值

判断知识卡是否带来与来源锚点相关的具体认知增量，而不是原文复述、换名、整理或笼统提醒。审核必须回答：删掉这张卡，读者会失去哪一个具体理解或判断能力？答不出时，价值问题必须在审核结果中明确暴露。

本维度不设数量配额、长度要求、分数或通过阈值。

### 3.2 事实

核对承重主张及其关键推论是否受到当前获授权证据支持，是否把不确定内容如实标明，以及引用能否追溯。不得把常识感、表达流畅或其他卡片的通过当作事实支持。

证据不足但仍可明确补齐时，应记录具体缺少什么证据；事实冲突或无法追溯时，必须记录冲突对象或断裂位置。

### 3.3 重复

在本次声明的待审集合内比较承重主张、解释作用与来源锚点，识别实质相同或一张卡已经完整包含另一张卡的情况。措辞不同不自动代表不重复，主题相近也不自动代表重复。

发现重复时，审核结果必须列出相关 `knowledge-card-id`，并说明重合部分及仍然独有的内容；不得推断当前审核范围之外是否存在重复。

### 3.4 边界

检查知识卡是否明确适用条件、失效条件与证据所能支持的范围，是否越过来源材料、授权范围或承重主张能够承担的结论。把局部观察写成普遍规律、把相关关系写成因果关系，或隐去关键限制，都必须作为边界问题记录。

边界判断不能新增产品事实，也不能替产品负责人决定材料授权或产品方向。

## 4. 四个审核终局

每张卡在一次完整审核中必须得到且只得到以下一个终局。终局记录必须同时保留四维结论，不能只留下状态名称。

### 4.1 锁定

当前证据与审核范围内，知识内容可以交给 Writer 统一表达。锁定是唯一允许写入 locked 集并进入 Writer 的终局。审核者不得借锁定之机改写卡片内容。

### 4.2 淘汰

当前受审知识内容不应继续进入 Writer。淘汰对该受审项是不可恢复的终局：它不得写入 locked 集，Writer、组装或其他下游节点也不得将其捞回、改名后恢复或用其他终局覆盖。

审核结果必须写清淘汰理由及对应维度。淘汰不等同于退回修改，也不能靠下游表达优化挽救。

### 4.3 退回

当前内容尚不能锁定，但存在明确的上游处理动作。审核结果必须指出需要重做、拆分、澄清或纠正的具体对象。退回项留在 raw 边界内；上游处理后必须重新接受独立审核，在新的锁定结论产生前不得进入 Writer。

### 4.4 待补证据

内容可能成立，但事实或适用边界缺少足够支持。审核结果必须列出缺失证据、该证据需要支持的具体主张，以及补证前禁止继续的范围。待补证据项留在 raw 边界内；补足证据后仍须重新审核，不得自动转为锁定。

本合同不预设某个维度的问题应自动映射到哪个终局。终局必须说明它如何回应四维结论，但不采用总分、权重、跨维度抵消或失败补偿规则。

## 5. 审核结果与 lineage

当前运行的完整审核结果写入：

`runs/<run-id>/raw/review-outcomes.md`

每条审核结果至少包含：

- 与输入逐字一致的 `knowledge-card-id`；
- 与输入逐字一致的 `producer kind`、`producer id`、`producer version`；
- 价值、事实、重复、边界四个维度各自的结论、理由与证据位置；
- 四态之一的唯一终局；
- 对淘汰、退回或待补证据项可直接执行的原因、处理动作或补证要求。

审核结果不得重新生成、归一化、缩写或替换 `knowledge-card-id` 与 `producer kind/id/version`。任何不一致都视为 lineage 断裂，并阻止 locked 集生成。

## 6. raw／locked 目录隔离

目录是下游读取权限的可执行边界：

1. 所有待审知识卡和全部四态审核结果保留在 `runs/<run-id>/raw/`。
2. 完整审核结果形成后，只把终局为锁定的原知识卡写入 `runs/<run-id>/locked/knowledge-cards.md`。
3. locked 集中的卡片内容及其 `knowledge-card-id`、`producer kind/id/version` 必须与受审输入原样一致；审核节点不得在复制时编辑或重写。
4. 淘汰、退回、待补证据项不得出现在 `runs/<run-id>/locked/`。
5. Writer 的知识卡输入白名单只有 `runs/<run-id>/locked/knowledge-cards.md`；Writer 不得读取 `runs/<run-id>/raw/knowledge-cards.md` 或 `runs/<run-id>/raw/review-outcomes.md` 来补选内容。
6. 若 locked 集与审核结果不一致、出现非锁定项或 lineage 不一致，必须阻止 Writer 启动。

locked 集为空不能自动证明产品合格，也不能被用来绕过独立审核。

## 7. 阻塞与决定权

以下纯技术缺口进入主控技术门，并必须在面向产品负责人的任务结果中可见：

- 输入身份、lineage 或引用不完整；
- raw／locked 路径隔离失效；
- 四维审核记录或唯一终局缺失；
- locked 集含非锁定项；
- 审核结果与 locked 集的 `knowledge-card-id` 或 `producer kind/id/version` 不一致；
- Writer 无法被限制为 locked-only 输入。

主控可以修复可逆的技术实现问题，但不能借技术修复改变内容终局、产品事实或材料授权。

遇到以下事项必须停止并交由产品负责人决定，技术侧与审核者不得代判：

- 需要产品价值判断才能解决的争议；
- 材料来源、授权或本次范围不明确；
- 缺少产品事实；
- 本合同与产品决议 owner 发生冲突。

单张卡已有明确补证路径但证据不足时，使用“待补证据”终局；不得把它伪装成产品负责人已经作出的决定。

## 8. 本合同明确不决定

以下内容保持未冻结，不得从本合同推断：

- 审核人数、角色数量、具体执行者或模型；
- 分数、阈值、比例、配额或通过线；
- 多份审核意见的聚合方法；
- 四个维度之间的权重、抵消或失败补偿规则；
- Prompt、批量大小、重试次数或调用粒度；
- 冻结后最终验收的实现、最终产品 gate 或产品接受标准。

这些未决定项不影响本合同的硬边界：只有锁定卡进入 Writer，淘汰项不可恢复，raw 与 locked 必须隔离，且审核结果与 locked 集必须原样保留 `knowledge-card-id` 和 `producer kind/id/version`。
