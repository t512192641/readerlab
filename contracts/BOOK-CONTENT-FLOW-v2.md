# 图书内容流合同 v2

## 1. 地位与目的

本合同是图书线从完整 B1 到就近 B2 的长期合同候选。它只派生
`PRODUCT-DECISIONS.md` 已确认的产品 owner，并以 `ENGINEERING-LESSONS.md` 与
`blueprints/PIPELINE-MAP.md` 约束工程边界，不新增产品决议或产品事实。若派生内容与产品 owner 冲突，
停止并以 owner 为准。

本候选只有通过独立工程审计并取得 `PASS`，才可由工程侧执行技术激活。图书内容流唯一 current pointer
的 owner 与路径是 `blueprints/PIPELINE-MAP.md`；其他合同、receipt、任务卡或 run 不得另立 current
pointer。

技术激活必须在同一 commit 原子包含：

1. 本合同 `status` 改为 `frozen`；
2. 产生一份绑定本合同冻结内容 hash 的新 freeze receipt；
3. `blueprints/PIPELINE-MAP.md` 中唯一 current pointer 切换到本合同。

三项未在同一 commit 全部完成时，本文件仍是 draft，不得被 runtime 或生产任务当作现行合同。不得先切
pointer、后补 receipt，也不得沿用 M1 receipt 为 v2 作证。旧五份合同及 M1 receipt 保持原样，继续作为
历史冻结证据；冻结激活后，它们不再定义当前接口，但仍不得被改写或删除。

技术合同激活不是产品接受，也不自动建立真实 runtime 集成或生产资格。未来真实产物的 `accepted` 仍为
`unknown`，只由产品负责人对绑定的冻结产物与固定 scope 给出。

本合同定义功能责任与交接 seam，不预先决定 Agent、Skill 或调用的物理拆分。一个实现可以合并适配器，
但不得合并职责、读取权限或 gate 结论。

## 2. 总流与最小接口

```text
冻结范围内的完整 B1
  → 控制层建立章节论证地图并选择认知背景
  → Expert 完整自由阅读，提交课程入口或沉默
  → 控制层聚类、检查重复与偏科，并作低成本内容价值晋级
  → 同一 Expert 形成完整内部专家课初稿
  → 初稿后知识审计、来源核验与语义锁
  → Writer 组织为一个或多个 Reader 单元
  → Fidelity 独立保真复核
  → B2 按冻结锚定关系确定性就近装配
```

长期只使用以下无歧义功能 gate 名称：

| Gate | Owner |
|---|---|
| `B1 范围就绪门` | Control |
| `认知背景路由门` | Control |
| `课程入口价值门` | Control |
| `专家初稿内容锁定门` | Content Review |
| `Reader 单元独立保真门` | Fidelity |
| `B2 装配门` | B2 Assembly |

`P1`、`P2`、`P3` 只可作为历史任务标签，不得出现在长期状态、权限、gate 或晋级语义中。

## 3. 信息隔离总则

- 所有模块只读取本次冻结范围与完成自身责任所必需的冻结上游产物。
- 生产端不得读取金标、样张、反例判词、裁判答案、评分表、其他 run 产物或最终验收答案。
- 控制层的章节论证地图、候选聚类、淘汰记录与价值检查不进入 Expert 输入。
- Expert 初稿、审计投影、来源核验、语义锁与 Reader 单元必须保持不同身份；任何投影都不能覆盖原件。
- Writer 不得读取淘汰内容；B2 不得读取未通过 Reader 单元独立保真门的内容。
- 产品判词只由产品负责人给出。任何模型分数、技术 `PASS`、gate 通过或流程完成都不能写成产品接受。

来源、范围、输入身份、读取权限或上游 gate 无法确认时，受影响模块硬阻塞；不得猜测、降级为摘要、
用字段齐全冒充语义合格，或从旧合同、旧 run 补齐。

## 4. 控制与认知背景路由模块

### 4.1 责任

控制模块承担生产控制，而不创作专家认知：

- 从完整 B1 重建只供控制层使用的章节论证地图，以保留作者的承重命题、重要分支、例证与开放问题；
- 选择能携带稳定知识背景的正式透镜或临时 Expert，同时保留主线相关与开放跨领域的探索空间；
- 检查从产品原始目标到背景选择、Expert 输入和输出的保真度；
- 管理课程入口聚类、重复、偏科、继续探索与停止；
- 在仍可低成本否决时判断课程入口是否值得进入完整授课。

章节论证地图只是控制工具。它用于选背景和后置保真检查，不是给 Expert 的问题清单、答案空间或课程计划。

### 4.2 输入

- 已通过 `B1 范围就绪门` 的完整作者单元及冻结范围；
- 已获准使用的认知背景信息；
- 当前任务的成本、调用与停止授权。

### 4.3 路由与受控偶遇

路由必须先判断可复用的正式透镜是否对本次完整 B1 真实适用；真实适用时优先使用其具体版本。只有没有
正式透镜能够承接、且仍存在真实知识缺口时，才可为当前材料和运行建立临时 Expert。正式透镜优先不是
固定名单优先，也不能用一个勉强相关的透镜堵住真实缺口。

每次发现都必须完成一次受控偶遇探索并保留可核对的执行证据。强制的是探索发生，不是非零入口；
受控偶遇可以合法沉默，零入口不自动表示语义合格或产品接受。受控偶遇使用的模型、调用次数、执行证据
schema、背景抽样和停止实现均为 `unknown`，只由当前任务授权。

### 4.4 输出

- 只供控制层使用的章节论证地图；
- 每次 Expert 派发所需的稳定认知背景；
- `formal-lens` 或 `temporary-expert` 的路由身份与版本 lineage；
- 课程入口版图、重复／偏科检查、晋级或停止结论及理由。
- 受控偶遇已执行的证据及零个或多个原始入口。

认知背景必须描述足以改变观察结果的稳定知识库存、经验、判断或思考框架，不能只是一组“检查、比较、
追踪、质疑”等分析动作。正式透镜可跨运行治理；临时 Expert 只服务当前材料和运行。正式透镜的发现、
版本治理和晋升细节保持 `unknown`。

### 4.5 不得下沉给 Expert 的内容

控制模块不得给 Expert 预设：

- 必答问题、局部锚点或优先原句；
- 期望结论、期望增量类型或候选主张；
- 指定课程、指定知识对象、固定来源或写作骨架；
- 固定课程数、概念数、来源数、字数或非零产出要求；
- 章节论证地图、入口聚类、历史失败清单或 gate 评分表。

### 4.6 失败动作

背景只有分析风格而没有稳定知识库存、路线会把 Expert 收缩成中央约稿答题者，或控制输入会预先决定
Expert 看见什么时，`认知背景路由门` 阻塞并退回控制设计。发现结果过早收敛到同一局部原文辨析时，
停止扩产并重新检查背景版图；不得用更多 Expert Prompt 负向规则补救。

## 5. Expert 自然发现与完整认知模块

### 5.1 首次发现与初稿形成时的最小输入

首次发现与初稿形成时，Expert 只取得：

- 本次冻结范围内的完整 B1 作者单元；
- 已通过路由门的稳定认知背景及其身份；
- 最小工作合同：完整阅读，把原文作为课堂中的真实案例，自由决定是否有值得教的知识。

返工态的唯一输入例外是第 7.5 节最小返工包。除此之外，Expert 不读取控制层地图、其他 Expert 输出、
入口聚类、淘汰记录、审计答案、Writer 结果或产品判词；即使进入返工态，也不得取得评分表、审核者
隐藏推理或其他审核答案。

### 5.2 低成本课程入口

Expert 完整阅读后可以提交零个或多个自然发现的课程入口，也可以沉默。沉默是合法结果，不自动表示
流程失败、语义合格或产品接受。

课程入口必须是短小但真实、足以保留 Expert 自然初始认识的原件，而不是一句候选主张、一个术语、
一个标题、一个问题或一份中央预制课程的应答。本合同不规定入口必须逐项回答哪些字段、问题或评审清单，
也不要求 Expert 预先证明控制层的判断。

入口只用于控制层低成本选择，不是读者产物、知识卡或锁定语义。控制层从该原件形成独立、可丢弃的
价值投影，再据此判断是否晋级；投影不得覆盖原件、回灌 Expert Prompt 或变成 Expert 的必答格式。
控制层可以拒绝入口，但不能替 Expert 补写认识后再晋级。

### 5.3 完整内部专家课

通过 `课程入口价值门` 后，由提出该入口的同一 Expert 形成完整内部专家课初稿。完整意味着读者未来
不仅能得到一个新增结论，还能理解知识如何组织、为何成立、何时适用，并能据此观察另一个问题；
它不要求固定栏目、固定篇幅或穷尽一个学科。

初稿必须同时保持：

- 原文是课程中的必要案例，而非装饰性引子；
- 知识拿掉原文仍有独立学习价值，换成无关原文又不能原样成立；
- 成熟知识、事实或实践传统、Expert 综合与应用到原文后的推论能够在后续显化和核验；
- 核心判断、必要关系、关键例子、来源边界与适用边界可被后续锁定；
- 不自然或不值得的连接可以停止，不为已晋级身份强行完成。

一份完整 Expert 初稿可以自然包含多张彼此相连的知识卡。不得因为最终读者文本可能需要压缩、合并或
拆分，就在 Expert 阶段把一堂连贯的课限制成一个局部小点或一个短评。

### 5.4 失败动作

若课程只能靠关键词、名称或表面比喻与原文连接，初稿只在原文内部做局部论辩，或只有标题与结论而
没有可学习的知识结构，停止该项并回到课程入口价值门；不得交给 Writer 扩写。需要改换课程时，必须
形成新的自然入口并重新晋级，不能在已晋级项内静默换题。

## 6. 课程入口价值门

### 6.1 控制责任

控制模块在完整授课和昂贵核验前：

- 按知识问题与谱系聚类全部入口；
- 识别术语换皮、实质重复、背景池偏科和仍未探索的空间；
- 判断真实触发、案例必要性、独立学习价值、领域主干性、生长性、重读原文的增益与认知成本；
- 根据是否仍出现新的高价值课程家族决定继续探索或停止。

课程数量与停止不设固定配额。停止属于控制责任，不是要求 Expert 必须产出、必须沉默或回答固定检查表。

### 6.2 输出与终局

每个入口只能得到以下一个控制终局：

- `晋级完整授课`
- `作为重复合并审计`
- `淘汰`
- `停止并保持 unknown`

“作为重复合并审计”只表示控制层识别课程家族关系，不允许合并或改写 Expert 的初始认识。淘汰内容
不得进入完整授课、Writer 或 B2。

### 6.3 失败动作

如果控制层只能证明入口新颖，却不能证明它值得存在，或必须先投入完整授课和来源研究才能看出其
基本价值，则不得晋级。若聚类或偏科检查缺失，停止扩产；不得以已有候选数、章节覆盖或技术完成替代。

## 7. 初稿后知识审计与内容锁定模块

### 7.1 角色

知识卡只在完整 Expert 初稿形成后产生，是对初稿的内部审计投影。它帮助审计：

- 内容价值及其对原文的真实作用；
- 来源与事实支持；
- 适用和失效边界；
- 课程内及本次候选集的重复；
- 需要保持不变的承重语义。

知识卡不能替代 Expert 阅读、发现、选课或完整思考，也不是 Writer 的一稿一单位。审计者不得借生成
知识卡重新命题、补写知识或把一份连贯初稿拆成互不相干的短卡。

### 7.2 输入

- 获准的完整 Expert 初稿及稳定 Expert lineage；
- 同一冻结范围内的完整 B1 与既有关系；
- 当前任务获授权的来源证据；
- 本次候选集内用于重复检查的只读对象。

### 7.3 输出

- 可回到初稿具体位置的知识审计投影；
- 来源核验结果，包括确认、错误标记与纠错要求、`unknown` 及其影响范围；
- 事实、边界、重复与内容价值结论；
- 明确排除的内容；
- 覆盖获准完整初稿的语义锁及冻结锚定关系。

语义锁必须保存获准初稿中已有的核心判断、必要关系、关键例子、事实范围和适用边界，并明确哪些内容
被淘汰或不得使用。来源核验只负责确认、标记错误、提出纠错要求和记录 `unknown`，不直接修订语义；
语义修订只能由原 Expert 形成新候选并重新受审。来源核验不能为满足引用数量替 Expert 命题，也不能用
来源名气代替内容价值。

### 7.4 `专家初稿内容锁定门`

每份初稿得到且只得到一个终局：

- `锁定并进入 Writer`
- `退回 Expert`
- `待补证据`
- `淘汰`

只有第一种终局可进入 Writer。退回与待补证据必须指出具体对象和动作，处理后重新审计；淘汰不可由
Writer、Fidelity 或 B2 捞回。任何内容修订都形成新候选身份，不覆盖既有审计证据。

### 7.5 退回态最小返工包

返工权限只在 `退回 Expert` 终局开放。审核者只标记错误及其影响，不直接纠正语义、代写新答案或把
审核判断变成课程内容。返工交接闭合后的最小返工包只包含：

- 错误在旧候选中的位置；
- 受影响的语义锁定项；
- 必须修正的事实或边界；
- 旧候选 lineage 与由原 Expert 形成的新候选 lineage。

返工包不是评分表、审核者隐藏推理、其他审核答案、其他 Expert 答案、金标或裁判答案。退回发出时先绑定旧候选及
原 Expert；原 Expert 依据最小返工包形成新的候选身份，交回时补齐新候选 lineage。新候选必须重新经过
完整知识审计与内容锁定门，不能继承旧终局、原位覆盖旧候选或被审核者直接改成通过。

`待补证据` 只开放补证，不开放语义改写；需要改变事实、边界或承重语义时必须转为 `退回 Expert`。
`淘汰` 与 `锁定并进入 Writer` 均不开放返工包。返工包的精确 schema 与序列化保持 `unknown`。

### 7.6 失败动作

无法从审计投影回到完整初稿、来源支持与主张范围不相称、语义锁未覆盖承重关系、冻结锚定关系歧义，
或淘汰内容无法从下游读取闭集中排除时，内容锁定门硬阻塞。产品价值争议、材料授权或产品事实缺口由
产品负责人决定；审计模块不得代判。

## 8. Writer 编辑模块

### 8.1 输入

Writer 只读取得：

- 终局为 `锁定并进入 Writer` 的完整 Expert 初稿；
- 对应语义锁；
- 来源核验结果；
- 为理解、忠实压缩与组织所必需的同一范围完整 B1 上下文；
- 冻结锚定关系。

必要完整 B1 是只读上下文，不授权 Writer 重新发现选题、从原文添知识或改变插入关系。Writer 不读取
淘汰入口、未锁定初稿、其他 run、金标、验收答案或产品判词。

### 8.2 责任与允许转换

Writer 把已经形成且获准的完整认知组织成正常成年人可读、清楚、连贯、可出版的读者文本。它可以：

- 删除重复和低收益支线；
- 调整顺序和段落；
- 压缩表达并合并相连内容；
- 按实际阅读体验保留为一个 Reader 单元，或必要时拆成多个 Reader 单元；
- 在不改变内容的前提下改善概念解释、节奏与衔接。

Writer 的组织单位是获准的完整 Expert 初稿与其锁定语义，不是知识卡。Reader 单元的数量由认识之间的
关系和阅读体验决定，不与知识卡一一对应。

### 8.3 禁止事项

Writer 不得：

- 选题、换题或决定淘汰内容重新进入；
- 新增事实、证据、机制、因果、结论、例子或适用范围；
- 删除承重推理，改变锁定语义或用流畅文字掩盖边界；
- 把来源审计表组织成文献综述来替代课程主干；
- 生成、修复、改变或重新选择锚定关系。

若只有新增知识或改变锁定语义才能写成可读文本，Writer 停止并退回内容锁定门，不得自行修复。

### 8.4 输出

Writer 输出一个或多个 Reader 单元。每个单元必须携带：

- 可读正文；
- 对所覆盖锁定语义的无损 lineage；
- 对应来源核验与边界的只读回链；
- 原样冻结的锚定关系；
- 同一 Writer 版本下可供 Fidelity 比较的稳定身份。

精确字段、schema、Reader 单元拆分算法与序列化方式保持 `unknown`。

## 9. Fidelity 独立保真模块

### 9.1 责任与隔离

Fidelity 独立比较 Writer 输出与锁定 Expert 语义，阻止编辑把内容改坏。它不重新选题、不评价课程是否
值得存在、不补事实，也不承担最终产品 Judge。

Fidelity 只读取得 Writer 输出、对应语义锁、获准 Expert 初稿、来源边界及必要 B1 上下文；不得读取
Writer 的隐藏推理、淘汰内容、金标、产品判词或最终验收答案。承担 Writer 生成责任的同一执行上下文
不得同时给出独立 Fidelity 终局。

### 9.2 `Reader 单元独立保真门`

必须逐项确认：

- Reader 单元完整覆盖其声称承载的锁定核心判断与承重关系；
- 压缩、合并或拆分没有添事实、添因果、改结论或扩大边界；
- 删除内容只属于获准删除的重复或低收益支线；
- 来源与 Expert 综合、原文应用之间的区分没有被抹平；
- 锚定关系与 lineage 未漂移，淘汰内容未被捞回。

终局只有：

- `保真通过`
- `退回 Writer`
- `阻塞并重开内容锁`

表达或组织可在锁内修正时退回 Writer；发现语义锁本身不足、冲突或无法支撑忠实编辑时，阻塞并重开
内容锁。只有 `保真通过` 的 Reader 单元可以进入 B2。

## 10. B2 确定性装配模块

### 10.1 输入与责任

B2 只消费：

- 当前冻结范围内的完整 B1；
- 已通过 Reader 单元独立保真门的 Reader 单元；
- 与这些单元一一绑定的冻结锚定关系、lineage 与稳定身份。

B2 按冻结关系把 Reader 单元确定性地装配到其回应的原文附近。它不创作、不审核、不改写、不重新选位，
也不拆分或合并 Reader 单元。装配视图不得截断完整作者单元、隐藏紧接上下文或冒充 B1 owner。

### 10.2 当前环境与未知接口

当前阅读环境是 Obsidian，并需要 `tandem-comments` 的正文附近批注与就地回复。精确
`tandem-comments` 接口、锚点格式、回复接口和所需 Obsidian Markdown 结构仍为 `unknown`，必须在真实
目标环境中另行验证后冻结。

旧 T1.7 的 `> [!note] AI 陪读｜标题` 不由本候选冻结，本合同不得恢复或暗示兼容。B2 输出格式在精确
接口确认前保持开放。

### 10.3 `B2 装配门`

装配门只做确定性检查：

- B1 逐字且完整；
- 每个 Reader 单元来自 `保真通过` 终局；
- Reader 单元正文未被装配器改写；
- 冻结锚定关系、身份和 lineage 未漂移；
- 就近关系可确定，且没有未获准内容；
- 输出没有猜测 `tandem-comments` 字段或恢复旧 callout 格式。

任一检查失败即停止受影响项或本次装配。装配器不得通过改正文、重选锚点、补字段或降低为章末汇总来
继续。装配通过只形成 execution 证据，不构成内容语义通过或产品接受。
