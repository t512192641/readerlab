# T1.6 Writer 合同

## 1. 目的

Writer 把已经锁定的知识卡统一为一条定稿标题和一份清楚、自然、可读的定稿正文。标题与正文都只改变表达，不改变已经锁定的知识选择、事实范围、承重主张、证据边界或价值判断。

本合同独立定义 Writer 边界，不以任何已生成的上游合同为前提。上游具体文件、schema 和审核实现尚未接入时，不能用推测补齐。

## 2. 唯一输入：锁定知识卡

Writer 的唯一内容输入是已经独立审核并明确标记为**锁定**的知识卡。每张输入卡至少必须让 Writer 原样取得：

- 稳定的 `knowledge-card-id`；
- 完整的 `producer kind/id/version` lineage；
- 原始来源锚点及其与 B1 原文位置的既有关系绑定；
- 已锁定的知识内容及其适用边界。

来源锚点／位置关系绑定、`knowledge-card-id` 与 `producer kind/id/version` 只用于原样回链和交给组装，不授权 Writer 读取其他产物、补充上下文或自行选择插入位置。

出现下列任一情况时必须硬阻塞，不得生成成品：

- 输入不是知识卡，或其锁定状态无法确认；
- 混入淘汰、退回或待补证据项；
- 缺少 `knowledge-card-id`；
- 缺少 `producer kind`、`producer id` 或 `producer version` 中任一值；
- 缺少来源锚点／位置关系绑定，或该绑定无法确认来自同一张锁定卡；
- 需要新增事实、主张、承重知识或产品判断才能写成标题或正文。

## 3. 允许的表达转换

Writer 可以在不改变原意、事实范围和边界的前提下：

- 为同一锁定焦点拟定一条定稿标题；
- 调整定稿正文的句序、段落和衔接；
- 消除重复、歧义、术语堆叠和不必要的字段腔；
- 把已锁定内容组织成连贯解释；
- 为可读性改写句子，但不得让改写产生新的事实、因果、结论或适用范围。

“只改表达”不是逐字复制要求。正常的重写、重排、压缩和连接均可进行，但定稿标题和定稿正文的每一处表达都必须能回到同一张锁定卡中已有的内容，且不得增加、删除或改变事实与主张。

## 4. 单焦点、单解释线

每张锁定知识卡对应且只对应一个 Writer 成品包，包内恰好包含一条定稿标题和一份定稿正文；二者必须：

- 只围绕该卡的一个焦点展开；
- 只使用一条连贯解释线把已有承重主张讲清楚；
- 不拼贴其他主题、其他卡片或旁支知识；
- 不为了显得完整而增加第二个主张或另起一条解释线。

如果一张锁定卡本身无法辨认唯一焦点或需要多条互不从属的解释线，Writer 必须阻塞并退回技术主控处理，不能自行拆卡、合卡或选择保留哪一部分。

## 5. 禁止事项

Writer 不得：

- 选题、换题或决定什么内容值得进入成品；
- 添加事实、承重知识、证据、机制、例子或推论；
- 重新审核价值、事实、重复、证据状态或适用边界；
- 重新做上游已经完成的价值选择；
- 捞回或改写淘汰、退回、待补证据项；
- 拆分、合并或跨知识卡拼接内容；
- 生成、修复、概括、替换或重新定位来源锚点／位置关系绑定；
- 选择、调整或推断定稿在原文中的插入位置；
- 因追求流畅而掩盖知识卡内容浅、证据弱或边界不清；
- 读取金标、样张、反例判词、裁判答案或本次输入之外的产物。

## 6. 输出与 lineage 不变量

Writer 对每张合格输入卡只产出一个成品包。每个输出包必须且只能包含一组一一对应的：

- 一条定稿标题；
- 一份定稿正文；
- 与输入逐值完全相同的来源锚点／位置关系绑定；
- 与输入逐值完全相同的 `knowledge-card-id`；
- 与输入逐值完全相同的 `producer kind`、`producer id`、`producer version`。

定稿标题与定稿正文都只是对同一锁定卡的表达定稿，均不得添加事实或主张。Writer 不得生成、替换、格式化、推导或补全来源绑定与 lineage 值，也不得用标题、顺序或文本相似度代替它们。输出包必须与输入卡一一对应；无法保持一一对应时必须硬阻塞。成品包的具体字段名、schema 与序列化方式尚未冻结。

## 7. 表达质量与内容价值分层

Writer 的表达检查只回答：

- 是否保持单焦点和单解释线；
- 是否清楚、连贯、自然；
- 是否忠实于锁定内容和边界；
- 来源锚点／位置关系绑定和 lineage 是否原样传递。

内容是否有真实认知价值、事实是否足够可靠、是否值得进入 B2，属于 Writer 上下游的独立验收责任。表达流畅不能替代上游知识质量，Writer 表达检查通过也不构成语义产品 gate、产品判词或 `accepted`。

当表达问题可以在不改变内容的情况下修正时，Writer 可继续改写；当问题实际来自内容选择、承重知识、证据或价值时，Writer 必须停止并交回技术主控，不得用文笔掩盖。

## 8. 与 T1.7 的职责边界

Writer 只交付一条定稿标题、一份定稿正文及原样来源锚点／位置关系绑定和 lineage，不负责 B2 组装，也不选择插入位置。以下事项不属于本合同：

- Obsidian callout 的生成或样式；
- 在原文中的插入位置与就近组装；
- `b2-item-id` 的创建、绑定或管理；
- `tandem-comments` 接口或精确锚点格式。

T1.7 只负责按既有来源锚点／位置关系绑定完成 callout 结构与物理组装，并管理 `b2-item-id`；它也不重新选择插入位置。`tandem-comments` 的精确接口仍为 `unknown`，不由 Writer 或 T1.7 补定。Writer 不读取样张来发明表达产品 gate，也不预设 callout、插入位置或 tandem 接口。

## 9. 硬阻塞与技术交接

以下纯技术缺口交给技术主控，并保持对产品负责人可见：

- 锁定状态、必需来源绑定、lineage 或一一对应关系不可机械确认；
- 输入结构不足以无损读取锁定内容；
- 输入或输出结构不足以原样携带来源锚点／位置关系绑定和 lineage；
- 单焦点或单解释线无法在不改变内容的情况下成立。

若缺口涉及新的产品事实、材料读取授权、产品价值判断，或 owner 文件之间出现决议冲突，Writer 不得代为决定；必须保持 `unknown` 并等待产品负责人决定。

## 10. 当前集成与验收状态

- `implemented`：本合同文件存在。
- `integrated`：当前没有真实 runtime 或真实入口使用本合同，明确未 `integrated`；M1 的合同组装或冻结不能建立该状态，只有未来真实入口实际消费锁定卡并交付本合同规定的成品包后才可能确认。
- `verified`：当前尚未由本执行会话单独主张；需同时通过针对本合同的确定性检查，以及主控对 owner、术语和职责边界的核验后才可确认。
- `accepted`：`unknown`，仅产品负责人可给出。
