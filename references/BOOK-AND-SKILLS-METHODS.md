# ReaderLab 借鉴方法卡

> 这里只保存“我们从哪些方法里学到了什么”。这些对象都不安装、不接入、不复制代码或 Prompt，也不能证明 ReaderLab 已经实现或通过。

## 曾明确研究的五个图书提炼 Skill

| 参考对象 | 借鉴什么 | 明确不照搬什么 |
|---|---|---|
| `cangjie-skill` | 全局理解后再做多视角深读；同时看结构、原则、案例、反例、术语和可迁移洞察；成品要经过多轮验证 | 固定视角数量；把每本书都加工成 Skill；照搬它的生态和文件结构 |
| `apple-ouyang/book-to-skill` | 主 Skill／子 Skill 的分层、触发边界、材料规模判断、真实场景自测 | “读完一本书就必须产出正式 Skill”的目标 |
| `win4r/book-to-skill` | 从全书主线到局部深读的认知路线，明确先读什么、读完能复述和使用什么 | 用漂亮目录或短摘要冒充完整理解 |
| `lijigang/ljg-skill-paper` | 论文深读中的缺口、增量、机制和可复核结论；追问材料究竟带来什么新理解 | 把论文单元强套给传记、图书、代码文档或 Skill 包 |
| `joeseesun/qiaomu-read-helper` | 按章节共读、正文附近批注、由读者问题驱动陪读 | 把“用户选中一段再问”当成系统主动发现高价值位置的替代品 |

五个对象共同留下的底线是：

1. 先完成声明范围的全局理解，再做地图、提炼或 Skill 化。
2. 多视角用于发现，不等于每个视角都必须交付内容。
3. 每个高价值判断都要能回到具体来源范围。
4. 提炼要说明新理解、适用边界和失败情形，不能只复述。
5. 成品要形成读者能走完的路线，而不是一堆互不相连的摘录。

## 后续外部机制调研

| 参考对象 | 借鉴什么 | 不借什么 |
|---|---|---|
| STORM / Co-STORM | 为单份材料临时生成少量视角；视角负责提问，证据负责回答 | 百科式覆盖取代原书、角色配额、固定角色直接出成品 |
| PaperQA2 | 先写独立 evidence note，再写成品；证据不足明确拒绝 | 用 chunk／RAG 代替作者结构；把相关度当内容价值 |
| Open Paper | 选区或锚点、局部解释、回跳原文 | 上传即摘要的产品目标；把被动选区当主动选题 |
| Readium / Thorium | 批注正文与目标位置分离；多种定位后备；独立可导出 | 整套阅读器、DRM 或 EPUB 互操作依赖 |
| Watchless | 主体路线与增强内容分开；先建完整证据账本；完整性审计不越权 | 视频处理依赖；把“证据齐全”当“内容有价值” |
| Anthropic `skill-creator` | 每个 Skill 用真实任务、baseline、冻结快照和盲比验证 | 用执行提升代替读者理解或 E4 产品证明 |
| Microsoft Deep Wiki | 包级目录和逐项源文件页分层 | 自动文档或导航替代逐 Skill 阅读 |
| Cisco Skill Scanner | 确定性事实、语义判断和不可分析三层分开 | 用安全扫描结果充当内容裁判 |
| Hypothesis / W3C Annotation | 多锚点、显式失锚、独立正文与目标、回复父子关系 | 直接接入外部服务或照搬 Web 定位格式 |

## 已经确定要进入新项目的共同机制

- **主体不能被增强内容替代**：图书保留作者原文，Skills 保留完整中文净化正文。
- **发现、证据、审核、表达分开**：发现者可以发散，证据卡负责承重，独立审核锁定后 Writer 才表达。
- **来源边界必须诚实**：目录级地图、局部深读和完整范围理解是三种不同状态。
- **未知是第三种状态**：证据不足、无法分析或锚点失效，不能静默算通过。
- **可逆性要单独验收**：恢复正文和恢复批注／关系是两件事。
- **事实审计不能冒充价值判断**：引用数、覆盖率、安全检查、目录完整和角色数量都不能直接当内容价值分。

## 仍未证明

- 这些外部方法在 ReaderLab 上的实际效果、成本、隐私、安全和界面体验都没有被本卡证明。
- 五个图书提炼 Skill 的历史研究已经找回；是否还存在其他曾被点名但未登记的对象，目前仍是 `unknown`。
- 真正采用哪些机制，必须在具体流水线节点中重新实现并通过真实样本验证。
