# T2.2 版本化恢复／复考架构 v1

## 1. 目的与非目标

### 1.1 目的

本报告为 T2.2 已失败的裁判资格考试定义一条最小、完整、可验证、版本化的恢复路线。
它要解决的不是“怎样把这次失败改成通过”，而是怎样先恢复一场有效资格考试所需的
对象、证据、隔离和判读边界，再以新版本留下不可覆盖的诊断与复考证据。

架构结论是：

1. 既有 T2.2 v1 是必须永久保留的失败证据，不能原位修补或重跑后覆盖。
2. 冻结 T1.8 继续只拥有“真实冻结 B2 单元的独立验收合同”这一责任，不因历史样张
   不具备 B2 身份而被改写。
3. 固定历史样张属于另一个对象域：`historical qualification fixture`（历史资格
   夹具）。后续应新增一个版本化、考试专用的中性适配合同，把 T1.8 的五项语义借给
   资格校准，但绝不伪造 `b2-item-id`，也不宣称这些样张是生产产物。
4. v2 只有在逐项恢复“一个判词范围对应一个候选单元”、同规则原文证据、盲测隔离和
   明确的绝对处置规则后，才有资格进入模型调用。
5. 先用一个两对象、配对、隔离的小型对照梯辨认 judge 能力、brief、对象、证据和批量
   影响；再决定复考模型与调用粒度。所有模型和调用仍须另行明确授权。
6. v2 即使通过，也只建立裁判资格的 execution／semantic evidence；后置审查和总控
   gate 通过前不得建立 M2，更不得进入阶段 3。

### 1.2 非目标

本报告不执行以下动作：

- 不调用 judge、模型、API、外部网络或付费服务；
- 不写生产代码、runtime、真实材料产物或阶段 3 文件；
- 不修改 T1.8、T2.2 任务卡、v1 packet、key、brief、answers、baseline 或 blocker；
- 不修改金标标签、产品通过线、产品决议或任何产品判词；
- 不创建 `diagnostics/M2-gate-receipt.md`；
- 不把 T2.1 或 T2.3 诊断产物加入 T2.2 资格输入；
- 不替产品负责人补写材料授权、对象级判词或 `accepted`。

## 3. 已确认事实

### 3.1 完整性与泄漏

1. 14/14 源文件 hash、提取片段 hash 与 packet payload hash 一致；源片段与 payload
   逐字节相同。
2. 既有记录称 judge 按四文件白名单运行、没有追问或第二次调用。
3. 仓库内可独立核对的 packet、brief 与 answers 没有 scoring key、源路径、预期类别
   或产品判词泄漏。
4. 第 2 项缺少 raw runtime 日志支撑，因此只能确认“冻结记录这样记载”，不能重放或
   完整证明当时平台上下文。
5. 上述完整性证明 v1 证据自洽，不证明考试对象有效，也不证明裁判合格。

### 3.2 对象与证据

1. v1 的 14 个中性 ID 都没有 T1.8 所要求的既有 `b2-item-id`、冻结生产产物可信身份
   及内容 hash、固定 scope。
2. 多个 v1 对象把整页或多条 AI 陪读合为一个对象；它们不是“一对象对应一个既有冻结
   B2 单元”。
3. 8/8 negative 带有正文上下文。
4. 3/3 positive 缺少与 negative 同规则、同用途、可追溯的完整原文锚点。
5. 因第 1—4 项，v1 历史样张不能被叫作 T1.8 的实际验收对象；给它们补一个新 ID 也
   不能补足缺失的生产身份、scope 或原文证据。

### 3.3 judge 实际判读表现

1. judge 对 8 个 negative 系统性地把原文明说关系的机制化措辞、换名或页内局部强段
   判断为实质增量，并全部 `放行`。
2. judge 对 3 个 positive 的解释深度、认知杠杆和呈现可作正向判断，但因缺少对应原文
   证据，把内容增量和原文关联记为 `unknown`，最终全部判为 `边缘`。
3. 该表现与“输入证据不对称”一致，但不能据此量化它造成了多少失败。

### 3.4 合同与 brief

1. 冻结 T1.8 已明确排除复述、整理、换名、同义改写和空泛提醒，并保留删除测试：
   “删掉这条，读者会失去哪一种具体理解或判断能力”。
2. T1.8 明确不冻结资格考试样本、计分、裁判配置、调用粒度、聚合和通过线。
3. v1 brief 要求五项判断及中性处置，但没有定义从五项到 `放行／拦截／边缘` 的考试
   专用处置映射。
4. v1 brief 没有要求 judge 显式留下“最小承重主张—原文明说集合—差分剩余”的操作
   记录。
5. T2.1 已明确是揭晓后的诊断探针，不是 T2.2 资格输入。

## 4. 已失效假设

以下不是根因推测，而是已被现有证据否定的技术假设：

### 4.1 “历史样张可以直接当作 T1.8 验收对象”

错误。T1.8 的 execution 前置面向既有冻结 B2 单元；历史样张没有该身份。资格校准可以
借用五项语义，但必须通过考试专用适配合同声明另一种对象身份，不能伪装成生产验收。

### 4.2 “一个源文件自然等于一个判断对象”

错误。多个源文件包含多条陪读或整页产物。源文件是证据容器，不自动等于产品判词的
最小适用范围，也不自动等于未来的一个 B2 单元。

### 4.3 “候选正文完整，就足以判断五项”

错误。内容增量与原文关联至少需要同一对象的可追溯原文证据。v1 positive 已直接显示：
候选自身可以解释充分、呈现清楚，但增量和关联仍因原文缺失成为 `unknown`。

### 4.4 “无标签泄漏就代表盲测有效”

错误。无泄漏是必要条件，不是充分条件。对象错位、scope 缺失或证据不对称都可以在
完全无标签泄漏时使考试失效。

### 4.5 “T1.8 的五项语言会自动产生统一处置”

错误。T1.8 故意不拥有聚合和失败处理。若资格考试需要 `放行／拦截／边缘`，必须由
考试专用、版本化规则拥有，且不得回写为长期产品门槛。

### 4.6 “一次 14 项批量足以证明或否定 judge 能力”

错误。一次批量只能证明这一固定配置、brief、包装、证据与批量组合产生了 v1 结果；
它不能单独把失败归给 judge、brief、包装、证据或批量中的任何一个因素。

### 4.7 “hash 链正确即可进入 M2”

错误。hash 链只证明字节身份和顺序。资格语义硬门已失败，因此 M2 仍是硬阻塞。

## 7. 推荐的最小完整架构

### 7.1 三个对象域严格分离

#### A. 真实生产验收对象

由冻结 T1.8 唯一拥有。对象必须是既有冻结 B2 单元，并同时具有：

- 既有 `b2-item-id`；
- 冻结生产产物可信身份及内容 hash；
- 固定 scope；
- 可追溯原文位置；
- execution／semantic／product 共用的同一身份。

历史资格夹具永远不得进入这个域。

#### B. 历史资格夹具

由新的考试专用适配合同拥有。它只用于测试 judge 能否按 T1.8 的五项语义辨认固定
历史对象。它使用 `qualification-item-id`，而不是 `b2-item-id`；它必须绑定：

1. `source-case-id`：当前 14 个固定来源组之一；
2. 产品判词权威与精确适用 scope；
3. 唯一候选单元边界及 SHA-256；
4. 对应原文上下文边界及 SHA-256；
5. 整个盲 payload SHA-256；
6. 预期类别，仅保存于 scoring side；
7. 版本与冻结状态。

资格通过只证明该夹具上的语义辨别，不证明 T1.8 execution 前置已经在生产 runtime
实现。

#### C. 评分与尝试对象

每次尝试拥有独立的 packet、key、brief、调用记录、answers、baseline 和失败 blocker。
v1、对照诊断、v2 复考互不覆盖；任何一次模型、brief、packet 或调用粒度变化都必须
形成新版本或新 attempt 身份。

### 7.2 历史夹具准入与对象粒度

后续准备侧先对 14 个固定来源组做完整候选 census，再决定能否各选出一个合法资格
对象。一个候选单元只有同时满足以下条件才可进入 hard-gate 考卷：

1. 它是一条完整 AI 陪读单元；标题、正文、限定和 caveat 不得截断。
2. 产品负责人已有判词明确适用于这一个单元，或判词原文明确声明该组中的每一单元均
   获得同一判词；不得从“整页一般”自行推断任一单条的标签。
3. 对应原文材料已在新项目内获得使用授权，且边界可无歧义提取。
4. 原文上下文和候选单元均逐字节复制；显示包装可以中性化，但正文不得改写。
5. 一个资格对象不得合并多条候选，也不得把一条候选拆成多个对象。
6. 判词 scope、上下文、候选、payload 与预期类别的 hash 链完整。

为保持既有“8 个 negative 来源组、3 个 positive 来源组、3 个 reference 来源组”
及其硬门而不人工挑最容易的单条，建议采用以下内容无关的选择规则：

1. 在每个来源组中按源文件顺序枚举全部合法候选单元；
2. 先由前置审查确认每个候选都满足上述准入条件；
3. 以固定字符串 `T2.2-v2` 和源文件 SHA-256 计算选择摘要；
4. 将摘要解释为整数，对合法候选数取模，得到唯一选择下标；
5. 在任何 judge 调用前把候选 census、选择公式、下标和结果冻结进 v2 key。

若某一 hard-gate 来源组没有合法原子候选，不得用整页代替、不得换别的文件补数、不得
降低 8/8 或 3/3；只能写 blocker，由产品负责人决定是否补充对象级判词或批准新的固定
考试集。reference 不参与硬门，但仍必须满足相同对象和证据结构，避免给 judge 暗示。

### 7.3 原文证据对称

“对称”不是要求每个对象字数相同，而是所有类别遵守同一提取规则。每个 v2 payload
固定为：

```text
qualification-item-id
SOURCE-CONTEXT-BEGIN
原文上下文
SOURCE-CONTEXT-END
CANDIDATE-BEGIN
一条完整候选陪读
CANDIDATE-END
```

原文上下文按同一机械规则确定：

1. 包含候选所回应的锚点段；
2. 包含候选明确引用或依赖的所有作者原文段；
3. 仅为消解代词、术语或论证关系所必需时，加入最近的前后作者段；
4. 到当前冻结 section／scope 边界即停止；
5. 不包含其他 AI 陪读、金标说明、文件路径、产品判词或评分 wrapper。

准备侧在 key 中记录逐段源坐标和 SHA-256；盲包只呈现中性边界与正文。positive、
negative、reference 都必须通过同一规则。任何对象缺失原始锚点、只能用摘要代替或需要
从旧项目取证时，整个 v2 packet 不得冻结。

### 7.4 考试专用适配合同

建议新增 `contracts/T2.2-historical-qualification-adapter-v1.md`，只拥有以下责任：

- 声明历史资格夹具不是 B2 单元，不需要也不得伪造 `b2-item-id`；
- 原样引用 T1.8 五项语义的含义，不删项、不替换产品标准；
- 规定资格夹具的身份、scope、原文证据和 hash 责任；
- 规定考试专用处置映射；
- 规定 judge 的中性输出结构和盲测白名单；
- 明确本合同不能用于阶段 3 生产验收、产品判词或长期产品 gate。

建议的 v1 考试处置映射是：

- `放行`：五项全部为正向定性判断；
- `拦截`：五项中至少一项为明确负向判断；
- `边缘`：没有明确负向判断，但至少一项为 `unknown`；
- 五项仍须逐项保留，处置不能代写五项；
- 该映射只服务当前固定资格考试，不写回 T1.8，不成为产品通过线。

这是架构推荐，不在本报告中冻结。前置审查必须确认它没有改变三个 positive、八个
negative 的既有产品类别或 8/8、3/3 硬门；若固定样张无法在这套映射下表达其原判词
scope，必须停止并升级给产品负责人。

### 7.5 绝对判断操作

v2 brief 应要求 judge 对每个对象独立留下以下操作证据：

1. 把候选压成一句最小承重主张，不补强候选；
2. 从所附原文上下文列出与该主张相关的原文明说集合；
3. 做集合差分：候选承重主张减去原文明说集合；
4. 判断差分剩余是否只是复述、整理、换名、明显推论或空泛提醒；
5. 对真实剩余检查证据支持、解释链、适用条件和失效边界；
6. 回答删除测试：删去候选，读者会失去哪一种具体判断能力；
7. 分别记录五项判断、对象内证据、原文证据、理由和边界；
8. 最后按考试专用映射给出 `放行／拦截／边缘`。

这是一项中性的绝对判断程序。judge 不读取 T2.1；brief 可以独立写出必要操作，但不得
引用 R01—R08、negative 模式、预期类别或任何产品判词。不同对象之间禁止排序、类比
或互相补证。

### 7.6 最小可信对照梯

v1 基线不能直接充当新因果实验的控制臂，因为它同时改变了对象、证据、brief 和批量，
且缺少 raw runtime 日志。后续若获模型调用授权，先从 v2 合法夹具中冻结两个 sentinel：
一个明确 negative、一个明确 positive。两个 sentinel 必须都有完整原文、原子 scope，
且在任何调用前由 scoring side 冻结。

建议最小对照如下：

| 臂 | 与控制臂唯一差异 | 对象／调用 | 独立重复 | 所区分因素 |
|---|---|---|---|---|
| C 控制 | 无：原子对象、完整上下文、v2 brief、单对象鲜会话 | 一正一负，各单独调用 | 2 | judge 在有效条件下的能力下界 |
| B brief | 只替换为绑定同一 packet 的 legacy-style brief | 同一正负，各单独调用 | 2 | brief／合同解释 |
| G batch | 只把同一正负放进一个 batch | 每次一个双对象 batch | 2 | 批量影响 |
| E evidence | 只移除同一对象的必要原文上下文，其他不变 | 同一正负，各单独调用 | 2 | 原文证据完整性 |
| O object | 只把同一来源组内、已有同标签的两条负例合并；上下文和 brief 不变 | 一个合并负例，单独调用 | 2 | 对象合并 |

最小调用数为 16 次鲜会话调用。它只给这两个 sentinel 上的局部方向证据，不允许外推
完整考卷。选择两次独立重复，是因为当前没有已冻结的确定性采样种子；单次变化只能
算观察，不能算稳定方向。

判读规则：

- C 两次都不能稳定命中任一 sentinel：当前 judge 配置的能力未得到证明，停止，不进入
  复考；换模型或推理档位需另行授权并建立新对照版本。
- C 稳定命中、B 稳定失去命中：支持 brief 影响；两者都命中则 brief 影响在该 sentinel
  上未显示，不能外推为不存在。
- G 相对 C 出现重复、同方向的退化：选择单对象鲜会话；否则 batch 影响在该 panel 上
  仍只得到有限证据。
- E 从可判变为 `unknown／边缘`：支持原文证据影响；若结果不变，只能说明该 sentinel
  未显示影响。
- O 相对原子负例出现重复的误放行：支持合并影响；若该来源组没有两个具有直接同标签
  的原子对象，则 O 臂不合法，该因素保持 `unknown`，不得伪造对照。
- 任一臂两次结果相互矛盾：该因素保持 `unknown`。只有该 `unknown` 会改变复考技术
  选择时，才扩大样本；否则采用更保守的单对象、完整证据路线。

对照结果只是诊断，不计入资格，不得让正式复考 judge 读取。

### 7.7 v2 正式复考

复考必须等待以下条件全部成立：

1. 资格适配合同已由前置审查确认且冻结；
2. 14 个来源组各有合法资格对象；
3. positive、negative、reference 均通过同一原文提取规则；
4. packet、key、brief 已冻结并形成完整 hash chain；
5. 盲包泄漏扫描和人工复核均通过；
6. 最小控制臂已证明所选 judge 配置在一正一负上稳定命中；
7. 模型、推理档位、调用粒度、调用次数和预算已获得本次单独明确授权；
8. 调用记录路径和写入所有权已在任务卡逐文件冻结。

复考的推荐默认粒度是“一对象一个鲜会话、无追问、无第二次机会”，因为它在 batch
影响仍为 `unknown` 时风险最低。若 G 臂给出稳定证据且总控基于成本决定使用 batch，
必须把实际粒度写进 v2 brief、answers 和 baseline；该决定仍需当次授权。

正式硬门不改变：

- 8 个 negative 必须 `8/8` 为 `拦截`；
- 3 个 positive 必须 `3/3` 为 `放行`；
- 3 个 reference 只记录，不放宽或替代前两组；
- 任一 hard gate 未满足即 `FAIL`。

失败时保留 v2 全部输入、原始 answers、baseline 和 v2 blocker；下一次只能建立 v3，
不得追问、改写或覆盖。通过时也只能交后置审查，不能自行创建 M2 receipt。

## 10. 后续角色、顺序和 gate

### Gate R0：产品材料与 scope 准入

**责任角色**：产品负责人提供／授权材料与已有判词 scope；技术准备角色只做提取和
核验。

通过条件：

- 3 个 positive 都有新项目内获准的完整原文锚点；
- 14 个来源组都能得到一个判词 scope 精确匹配的原子资格对象；
- 不需要回旧项目取证，不需要改变 8/8、3/3 或标签。

失败动作：停止；不得创建 v2 packet。涉及材料授权或对象级判词时，只能由产品负责人
决定。

### Gate R1：前置审查

**责任角色**：独立架构／验收审查角色，不参与 v2 夹具编制。

审查内容：

- T1.8 与 qualification adapter 的责任是否分离；
- 对象是否单一、判词 scope 是否直接适用；
- 三类输入是否执行同一原文上下文规则；
- payload 与源片段是否逐字节一致；
- key 是否私有、packet／brief 是否无泄漏；
- v1 所有冻结证据是否未修改；
- T2.1、T2.3 是否完全不在 judge 输入；
- 状态头、版本、hash chain 和写入路径是否完整。

只有 `diagnostics/T2.2-preflight-review-v2.md` 为 `PASS`，才能请求模型调用授权。

### Gate R2：最小对照诊断

**责任角色**：隔离 judge 执行角色与独立 scoring side；二者不得共享 key。

通过条件：

- 控制臂一正一负各两次稳定命中；
- 其他臂结果足以选择保守调用粒度；
- 矛盾结果如实保持 `unknown`；
- 模型、调用、预算均有本次明确授权；
- 对照答案未进入正式复考 judge 上下文。

控制臂失败即停止，不得用正式 14 项复考继续试模型。

### Gate R3：正式复考执行

**责任角色**：准备／scoring side 编排；fresh isolated judge 只写各自原始答案。

通过条件：

- 使用 R1 冻结的 v2 输入；
- 实际模型与调用粒度等于授权和 brief 记录；
- 无追问、改答、第二次机会或 key 泄漏；
- 8/8 negative `拦截` 且 3/3 positive `放行`；
- baseline v2 绑定完整输入和答案 hash chain。

失败即写 v2 blocker，保留全部证据并结束。

### Gate R4：后置审查

**责任角色**：未参与准备、调用或评分的独立审查角色。

审查内容：

### Gate R5：总控是否允许进入 M2
